# 可选图片后端

角色参考图、场景/道具图、关键帧和整张分镜板共用 Canvas 图片节点，可选 `codex-imagegen` 或 `comfy-qwen-image`。切换保留提示词、素材、各后端参数和历史结果，只影响下次生成；不会自动重试或换后端。

Codex imagegen 由具备真实图片工具的宿主领取 Agent 请求。Qwen 由本机画布服务执行，浏览器可以直接确认和查看结果，无需 Codex；提示词可由用户或其他助手准备。

## 环境

需要官方本地 Comfy MCP、其内部使用的官方 comfy-cli、已有 ComfyUI 安装、FFmpeg/FFprobe。画布通过 MCP 完成启动、上传、预检、提交、查询和取回；项目连接配置见[本机环境](local-windows.md)。不自动安装模型或启动备用实例。

模型配置为 `qwen_image_2.1_int8_convrot.safetensors`、`qwen3vl_8b_int8_convrot.safetensors`、`qwen_image_2.1_vae_bf16.safetensors`。每次提交前预检原生 Qwen 2.1 节点及模型，缺失时停止，不换权重。参考来源：[Comfy-Org 模型](https://huggingface.co/Comfy-Org/Qwen-Image-2.1)、[ComfyUI 工作流模板](https://github.com/Comfy-Org/workflow_templates)。本地模板和实际节点实现是本适配的验证依据。

## 模式与参考图

| 模式 | 图片输入 | 用途和尺寸 |
|---|---|---|
| 文生图 `create` | 0 张 | 初始角色、场景、道具；填写画幅和像素预算 |
| 图片参考生成 `reference` | 1～10 张 | 参考人物/场景/道具生成新构图或分镜板；填写新画幅和像素预算 |
| 图片编辑 `edit` | 1～10 张 | 第 1 张为目标，其他至多 9 张辅助参考；跟随首图处理后的尺寸 |

10 张是总输入上限，包含编辑目标。底层节点的其他槽位不作为项目承诺。数量支持不等于十张高分辨率图均能在当前显存稳定运行；首轮对比实测了 1、3 张，10 张真实负载需单独验证。

界面按实际输入顺序标记图号，可上移/下移。一个上游有多张输出时占连续图号，需要单张排序可分别导入素材节点。上游未完成时图号只是草稿提示，确认以解析的实际输入为准。调整顺序后同步检查提示词编号。`related` 资料连线不参与生成。

提示词用 `<image1>` 至 `<image10>` 指定用途，例如：“保留 <image1> 的人物身份，采用 <image2> 的候车室空间，手持 <image3> 的钥匙，生成以下 2×2 电影分镜板……”。不能引用不存在的图号。

编辑说明改变项和保留项，例如“仅改变 <image1> 右下格的表情，其他格的人物、构图、服装、道具状态保持一致”。这不是蒙版编辑或像素锁定，验收时检查其他区域是否被连带改变。

## 提示词准备与执行边界

当前没有自动提示词改写或扩写步骤。创作侧按资产用途选模板：影视角色卡/分镜用zero-to-story，产品/服装/海报/最终网格用[visual-design-creator模板](../.agents/skills/visual-design-creator/SKILL.md)，由用户或助手整理后保存到图片节点；Canvas 确认时冻结文本，执行器原样传给 `TextEncodeQwenImage21`。原生编码器的固定系统包装用于文本与图片条件编码，不会产出一份改写后的提示词。

参考编辑优先把变化写在前面，再说明必要的保留项；参考图已表达清楚的外貌不必重复罗列。位置关系先确定观察方向，再写清物件所在的桌面、左右与远近，例如“从前门朝后墙看，电话和台灯都在右侧同一张工作台上，电话靠近镜头，台灯靠近后墙”。这属于确认前的创作准备，不在执行器内暗改提示词，也不保证模型一定遵从。

排查时一次只改变一个因素，并分别检查指令是否执行、身份是否保留、画质是否可用。缩短指令后动作改善，不能据此认定画质问题已经修复；单张通过也不能证明跨镜头空间稳定。

## 参数与透明输出

- 新构图 1 MP 为约 1024×1024 像素，按画幅计算后宽高分别对齐 32；允许 0.25～4 MP。实际尺寸随产物记录。
- 编辑不接受新画幅或输出像素预算。切换模式后保留旧值并提示清空，不静默忽略。
- `reference_resolution` 为参考图预算边长：1024 表示每张约 1024² 像素且保持比例；0 保持原尺寸再对齐 32。默认 0 与首轮对比一致。多图或大图可明确降低该值，程序不自动删图或降质。
- 默认 25 步、CFG 1、Euler/simple、denoise 1；参考模式用 Qwen cache。25 步是实测基线；原工作流说明 Euler 官方路径约 40～50 步，不把 25 当质量上限。CFG 1 下不提供无效的负向提示词项。
- 参考生成和编辑可用高级参数 `cache_device` 选择 `auto`（默认）或 `off`。关闭原生参考缓存会增加计算量，仅在排查结果异常时用于同输入对照；实际选择写入运行记录，不因失败自动切换。
- `attention_backend` 默认沿用服务设置；选 `pytorch` 时，仅为本次图片模型使用原生 PyTorch 注意力，不改变其他任务或模型权重。
- 未填种子时生成并记录。`conditions.json` 保存实际尺寸、种子、步数和参考图摘要；`workflow.json` 保存实际提交图。种子不能跨模型保证相同结果。
- 去背景使用 edit，在提示词明确 RGBA 透明背景，并启用“要求真实透明背景”。文生透明素材也须写明要求。此开关只做技术验收，不偷偷修改提示词；必须有实际透明度和可见主体才成功。PNG 保留 Alpha。

## STEP 2、STEP 3 与恢复

角色卡、分镜板和关键帧复用 [zero-to-story 视觉资产规范](../.agents/skills/zero-to-story/references/creative-assets.md)与其中的单一模板。本段只适用于影视角色卡/分镜用途；产品/服装/海报/最终展示网格采用视觉资产专能模板，不强制故事板无网格规则。后端不改变身份/覆盖状态和声明用途；最终六格为同步构图，规划分镜才按时刻。

角色卡检查身份、衣着和关键道具；分镜板检查布局、人物关系、道具归属与完成状态；编辑检查要求保留的区域。图片解码成功不代替内容接受，两边沿用相同标准。

图片与本地视频共用单个 GPU 资源及机器锁。CLI 提交一次，未知状态保留原回执，不重试。为兼容旧视频回执，状态目录和 `LFO_VIDEO_STATE` 保持原名，诊断仍用 `python -m lfo.comfy.admission`。共同规则见[共享生产规则](ai-system-prompt.md)。实际图片验收需完整解码、核对尺寸与透明度，记录实际文件及未验证项。

## 参考生成的尺寸敏感问题

本机发现参考生成可能出现大范围粗糙纹理、过度锐化或编辑不生效。增加步数、关闭参考缓存、切换 PyTorch 注意力均未修复该样例；参考图单独经过 VAE 编解码正常。调整参考图处理尺寸会改变异常表现，不能只检查预算参数是否为 1024，也不能把这种画质问题归因于提示词。

对于本机已测的 1248×832 人物基准，参考模式保持 `reference_resolution=0`，仅将 3:2 输出预算从 1 MP 改为 1.05 MP（实际 1280×864），消除了大块异常纹理。编辑模式显式设置 `reference_resolution=1056`，输出 1280×864，也通过了转向与换光线检查。仅改参考预算、仍输出 1248×832 时背景异常保留；参考图与输出同尺寸不是充分条件，也不是必要条件。这些是具体样例的规避条件，不是所有尺寸、素材或模型版本的通用修复；不要自动改用户指定尺寸、覆盖默认值或失败后重提。

正式复用角色或场景前，用实际素材和计划尺寸检查一次修改效果及原本平滑的背景、皮肤、衣料。发现同类异常时停止采用及依赖生成，保留条件记录；只有修正后的实际图通过检查才继续。上游有相似报告 [#16435](https://github.com/Comfy-Org/ComfyUI/issues/16435)、[#16607](https://github.com/Comfy-Org/ComfyUI/issues/16607)，尚不能据此认定本机的具体代码根因。

## 多图实测补充

本机已通过画布和官方 CLI 完成文生图、单图角色卡、三图合成、分镜生成/编辑、透明背景，以及10张参考图的技术回填。10图采用每张约512²参考预算，实际出现重复角色和人物融合；输入数量支持不代表角色关系和画面质量可靠。生产优先选少量、用途明确的身份/场景/道具参考，逐张说明用途。尚未验证10张高分辨率原图的显存与质量表现。
