# 项目共享生产规则

本文是协作和媒体生产规则的唯一来源；[AGENTS.md](../AGENTS.md) 补充技术、数据边界和验证入口。历史记录与示例仅供参考。一次只读当前交付需要的 Skill 和引用，已读且未变化的规则不重复加载。

## 职责与最小交接

主会话负责故事、导演决定、准确对白、验收要求、阻塞处理和最终交付。执行子代理完成一个明确的工作单元，例如提示词、素材准备或结果检查；不另设监控代理或项目级模型调度器。子代理沿用当前宿主生效的子代理模型和推理配置，不复制主会话设置或写死型号；宿主要求显式参数时只传已核实的配置，取不到不猜。

交接只传：单元编号与源版本、当前 Panel 的创作事实和关键验收要求、必要素材、已有授权范围、输出位置、适用 Skill、完成条件和阻塞边界。不要传整章历史、重复规则或无关日志。返回实际文件、采用结论、有关的末态/音频证据、未知项和依赖状态；不编造路径、任务 ID 或完成结果。

## 生成前：当前输入可执行

Windows 新环境先按[环境准备指南](windows-setup.md)做只读预检。项目预检和启动只提醒缺少的依赖，不自动下载安装；用户自行准备，或明确授权后由 Agent 按实际环境分析并执行安装。普通创作或启动授权不包含依赖安装。干净 Git 仓库只分发代码和通用资源，不迁移 Canvas、ComfyUI、小说故事等用户私有数据。

Panel 指一段独立生成的视频。它的时长、动作、提示词、必要素材、所选能力要求的参数、音频/对白与后期责任、输出位置和授权齐全后即可 ready。独立 Panel 的缺失素材不阻塞当前 Panel；依赖前段真实末态时，等待前段 `ACCEPT` 和所需真实尾帧。准备工作可按资源并行，视频提交串行。

创作要求写成少量可观察的关键事实：观众必须看懂什么动作或关系，哪些身份、道具、文字或声音不能错，以及由生成还是后期负责。数量、形状、接触等细节仅在影响当前镜头时展开。不要把每个风格形容词变成验收条款。

有人物连续性需求时，主会话在当前创作源维护固定人物文字和适用造型，覆盖跨镜配角、旁观者与背影；T2VA、I2VA、FL2VA、R2V 均按[人物文本锚点](../.agents/skills/zero-to-story/references/creative-assets.md#人物与场景文本锚点)继承，有图也不省略必要辨识信息。用户只给大致剧情并授权自主创作时，由主会话补齐必要可见设计、检查逐人覆盖和实际结果，不要求用户逐镜提醒。登记人物不强制新增角色图；图文冲突先修正当前输入，不靠生成模型猜测。

依据当前宿主实际能力准备输入。Agent 型能力用本会话的 `host_tools` 验证；浏览器可排队用户明确选中的已安装能力，但领取时必须再验证执行宿主。缺少能力时保留用户选定的提供方、输入和参数并说明缺口，不静默换后端或改创意。

### 概念单一权威

同一生产概念只在一处给出定义性文字，其余位置用指针引用。共同的创作、执行与验收规则以本文为权威；目标到主 Skill 的路由见[Skill 路由](ai-skill-routing.md)；画布字段与接口见[画布指南](canvas-guide.md)。禁令必须写明被禁止做法以及可采用的替代供给，不只写“不要”。断言与检查锁住稳定约束，不锁会漂移的字面数量。Skill 或参考中的定义若与本文冲突，以本文为准并修正来源，不双写。

规则分三级，冲突时按 **硬约束 > 条件约束 > 创作建议**，同级再按定义权威方优先：

| 级别 | 含义 | 违反后果 | 例 |
| --- | --- | --- | --- |
| 硬约束 | 违反则输入不可执行或产物不可用 | 阻塞 / FAIL | 三项关键硬门、Canvas 唯一执行、锁定对白逐字 |
| 条件约束 | 仅在声明条件成立时适用 | 该场景下阻塞；条件不成立则忽略 | “仅 R2V 可见演唱绑定音频”“仅连续接力要尾帧” |
| 创作建议 | 提升可看性与可说性的参考 | 不阻塞，可被明确创作理由覆盖 | 节奏策略、构图偏好、微表情写法 |

机器检查只对硬约束与可算术的条件约束下结论；创作建议不进 FAIL。无法机械判定时记 `unverified`，不把“检查不了”写成通过，也不升级为用户裁定关卡。

### 关键硬门（仅此三项未指定则停下询问）

下列三项决定输入是否可执行，且事后难以补救。未指定或含糊时**停下来把选项摆清楚**，不默认跳过、不替用户推断。其余制作规格（画幅、单段时长、像素与采样等）可按能力与上下文推断并记录依据；推断不是用户已选择，可被用户改写。产品、合规与授权事实缺失时列为阻塞缺口，不是弹窗默认项，也不得编造。

| 硬门 | 必须确认什么 | 正例（可推进） | 反例（必须停） |
| --- | --- | --- | --- |
| 1 生成模式 | 当前 Panel 是 T2VA / I2VA / FL2VA / R2V 中的哪一种（用户未指定模式时停下问；模式选定后缺必需媒体由系统/机检拒绝，不为此打断用户） | 用户指定“用上一张角色图作首帧做图生视频”，且首帧已就绪 | 只说“做一段视频”却未定是否需要精确首帧/尾帧/参考控制 |
| 2 跨 Panel 尾帧依赖 | 本镜是否真实连续上一镜末态；若依赖，须前段完整 `ACCEPT` 并绑定真实尾帧（`source_run_id` + `require_accept`） | 用户明确“同一镜头接着演”，前段已 ACCEPT 且尾帧已提取绑定 | 只因同场/同场景就自动接尾帧；或在前段未 ACCEPT / 尾帧来源不明时仍要求续演 |
| 3 可见演唱或对口型音频 | 人物是否可见地演唱/说唱；若是，须对应真实歌曲/语音窗口绑定 `ref_audio_0` 与 `<Audio N>` 槽位说明 | 用户要求对口型唱歌，且给出采用音轨同窗片段与绑定方式 | 只有歌词文本或仅有首帧却声称“原曲驱动口型”；无张口镜头却强行加音频参考 |

硬门确认结果写入当前创作源与对应计划的 `user_constraints` / 授权依据，标明适用范围。沉默、超时或含糊的“继续”不建立新授权，也不因此增加本文以外的审批关卡。

### 素材就绪形态（按真实状态，不按节点存在）

就绪程度只由**实际运行与审片状态**决定，不由“画布上有没有这个节点”决定：

| 形态 | 判定 | 允许的表述 |
| --- | --- | --- |
| 待生成（规划文字） | 仅有提示词/计划/节点草稿，尚无成功输出 | “待生成 / 规划中” |
| 已产出待审 | `run` 成功且尚未形成有效 `review.decision` | “已产出，待审” |
| 已采用 | 有效 `review.decision` 为 ACCEPT，且 `output_path` / `output_sha256` 与实际文件一致 | “已采用（附 run/摘要）” |
| 不可用 | REJECT / INCONCLUSIVE / 失败 / 来源或授权无法核实 | “不可用（原因）”；相关依赖阻塞 |
| 不适用 | 当前 Panel 本就不需要该素材（如 `visual_asset_policy: none`、无张口镜头不绑音频） | “本 Panel 不需要” |

节点存在、文件名像真的、相关资料边、单独角色卡或历史成功 run 都**不**等于本项已采用。禁止把待生成或待审写成“已核验 / 已稳定 / 已传递”。REJECT 与 INCONCLUSIVE 不是永久终局：派生版审片与带原因重开见[视频验收·后期与采用状态](../.agents/skills/zero-to-story/references/video-qc.md#后期与采用状态)。详见[素材用途检查](../.agents/skills/zero-to-story/references/creative-assets.md)。

## 唯一执行入口

页面和宿主都通过节点画布服务操作。修改前读取最新画布、选择与版本；保存只是草稿。页面确认或对话明确授权后，服务冻结当次输入并创建一次运行。已有持续授权覆盖当前范围与精确输入时直接复用；范围或输入变化时核对其是否仍被覆盖。沉默、超时或含糊的“继续”不建立新授权，也不额外增加审批关卡。

所有 Comfy 生成任务（包括 TTS 和技术试听）都必须经过画布确认与服务执行链，不提供绕过画布的 HTTP、CLI 或独立脚本提交入口。尚未接入画布的能力只做只读预检和工作流准备，并明确报告能力缺口；不能用其他媒体类型冒充该能力。只读诊断与服务内部调用不构成额外生产入口。

- **Agent 型能力**：具备真实工具的会话独占领取 `pending_agent`，使用冻结输入提交一次，回填实际媒体。
- **本地 Comfy 视频**：确认后为 `queued`，由服务内部 worker 原子领取并启动项目 `comfy-video-executor` adapter。adapter 使用画布自己的官方本地 Comfy MCP 会话上传、预检、单次提交、查询原任务和取回产物。它不经过 Agent claim，对话不能重复启动脚本。
- **本地 Qwen 图片**：选择 `comfy-qwen-image` 后同样为 `queued`，由 worker 启动项目 `comfy-image-executor`，共用 MCP 执行链。与本地视频共用资源和机器锁，无需宿主图片工具。输入规范见 [Qwen 图片指南](qwen-image.md)。
- **本地 Qwen TTS**：`audio` 节点选择 `comfy-qwen-tts`，确认后由 worker 启动 `comfy-tts-executor`，共用 Comfy 提交链、资源与机器锁。原始音频保留，节点回填按所选语速处理后的实际音频；见 [Canvas TTS](canvas-tts.md)。
- **本地 Music 3**：`audio` 节点选择 `comfy-minimax-music`，确认后由 worker 启动 `comfy-music-executor`，共用 Comfy 提交链、资源与机器锁；保存真实 FLAC 与实际时长。`max_duration` 是上限，采用前须听审；见 [Canvas Music 3](canvas-music.md)。
- **本地人声分离**：`audio` 节点选择 `comfy-singing` 的 `separate`，由 worker 启动 `comfy-singing-executor`，共用 Comfy 提交链、资源与机器锁。只执行 MelBandRoFormer，兼容保留历史模型标识 `melband-seedvc-44k`；已撤下失败歌声试验的转换/直唱模式，历史运行与媒体保留。见 [分离执行 Skill](../.agents/skills/comfy-singing-executor/SKILL.md)。
- **失败或未知**：停止受影响单元及其依赖，核实原请求；不自动重提、换提供方或把失败候选登记为正式产物。其他独立工作继续。
- **本地 YuE2 翻唱**：`audio` 节点选择 `comfy-yue2-music`，由 worker 启动 [comfy-yue2-executor](../.agents/skills/comfy-yue2-executor/SKILL.md)，共用 Comfy MCP 与机器锁。SheetSage2 自动提取参考旋律，YuE2 重建演唱和伴奏；不承诺参考音色、固定五歌手身份、原始伴奏或精确口型时序。按匹配歌词执行一次，真实 FLAC 回填后听审。

本地 ComfyUI 离线时，共享 MCP 连接层调用 `launch_comfyui` 启动已配置安装并等待就绪，无需用户另外启动 Desktop。启动使用同一回环地址与既有模型环境；已有服务直接复用，启动超时保留启动标记，不重复创建实例。此授权不包含安装、更新、替换模型或重复提交生成。

生成任务的生命周期与 ComfyUI 服务分开：任务结束只释放该执行连接，不关闭服务或主动清除模型缓存。Windows 离线启动由项目独立常驻连接持有，避免临时 MCP 会话的进程树清理连带终止服务；正常任务复用在线实例，常驻观察失败不自动重启。具体状态和恢复规则见[本机环境](local-windows.md)。

Comfy 的 `VideoSubmissionGuard` 以机器级互斥覆盖提交和整个等待周期。进程丢失后，持久回执继续阻塞未知任务，直到根据原任务证据核实结束。回执以 Canvas `request_id` 标识，位于应用数据目录 `zero-to-story/video`，可由 `LFO_VIDEO_STATE` 指定。诊断用 `python -m lfo.comfy.admission`；`--reconcile REQUEST_ID` 通过 MCP `job` 只读核实原任务，不重提，也不替代画布状态核实。

如果操作员确认 ComfyUI 重启等事件已使原任务失败或取消、原历史无法再查询，可用 `--operator-reconcile REQUEST_ID --provider-task-id TASK_ID --terminal-status failed|cancelled --reason "..."` 记录核实依据并解除完全匹配的回执。该路径只接受原 Canvas 请求编号和原 Comfy 任务编号，先写入应用数据目录的核实审计记录，再清除回执；它不会改变 Canvas run 状态，也不会提交新任务。`prompt_not_found`、空队列或历史缺失本身都不足以作出失败/取消判断；必须由操作员实际确认原任务终态。

女团、男团或混合组合需要可辨轮唱时，由 [音乐与 MV Skill](../.agents/skills/music-video-creator/references/multi-singer-workflow.md)组织已采用原曲、完整 YuE2 翻唱候选、分离与整句混音。保护原曲伴奏、旋律、Hook 和时间轴；完整混剪听审后冻结实际声源与角色映射。H3 可见演唱使用最终主音轨同窗口片段，按真实槽位绑定 R2V，实际口型仍须验证。人数可配置，但生成次数不证明音色人数，原曲已有和声不等于各角色独立和声。

仅原回执没有远端编号时，另提供已核实旧实例停止、新实例启动的恢复分支：用 `--server-restarted-at <含时区的ISO时间>` 替代 `--provider-task-id`，并给出实际观察原因。重启时间必须晚于原提交且不晚于当前时间，MCP 必须确认原地址服务已就绪。先持久保存原回执和重启证据再解除占用，随后用同一证据核实原 Canvas 请求为失败或取消；不推断原任务曾经成功，不伪造编号，也不自动重提。具体操作见[本机环境](local-windows.md#诊断与恢复)。

## 产出后：一次必要验收

普通文件或技术组件回填实际文件和技术状态即可。故事生产或用户要求内容验收时，对实际交付版本做一次检查；技术提交成功不等于内容接受。

先确认文件可用，再对照当前任务的关键要求查看画面、连续运动和有关声音。仅记录与叙事、使用目的或下游依赖有关的事实：例如交接镜头的道具归属与完成状态，口播的对白、可懂度与同步。无音频的视频明确记为无音频；图像不套用视频听审清单。接口要求的字段保留，用简短观察填写，不扩成全量表格。

- `ACCEPT`：关键要求有实际证据支持。
- `REJECT`：已确认的错误妨碍用途。
- `INCONCLUSIVE`：关键证据不足；保留未知，停止相关依赖。

有关键疑点时只对该窗口做一次局部复核；仍不清楚就保留未知。轻微且不影响用途的差异直接注明即可。默认不打分、不多模型投票、不反复自审、不写重复 QC 报告。抽帧、轨道存在、模型描述和不确定的 ASR 不能冒充实际视听证据；工具无法验证的项目如实说明。

仅在下游需要精确首帧时，从已 `ACCEPT` 的实际采用视频提取真实尾帧。后期修改会产生新版本，应检查改动及受影响的接缝；旧版本结论不能替代新文件检查。最终成片完成全部后期后做一次完整视听检查：故事分镜按需读[故事视频验收](../.agents/skills/zero-to-story/references/video-qc.md)，MV按需读[MV后期与验收](../.agents/skills/music-video-creator/references/finishing-and-review.md)，广告按需读[广告后期与验收](../.agents/skills/advertising-creator/references/finishing-and-review.md)。

确定性编辑只处理已有授权内、执行者已核实可以删除的静音区间，保留受保护对白和句尾余量；ASR/VAD 只用于定位。编辑后核对受影响的字幕、画面、声音和同步，不为每个静音区间增加审批。

## 持续生产与结束

只有持续生产需要登记接续；普通问答、代码审查和未启用的画布不纳入。开始时按[接续指南](canvas-continuation.md)绑定真实宿主会话、画布组件范围和已有授权。实际派发成功才记 `dispatched`，结果返回记 `result_ready`，主会话核实并处理后记 `handled` 或带原因的 `blocked`。这些状态不授予生成权限，也不替代 `ACCEPT`。

主会话收到结果后，实际启动下一项已授权且输入齐全的工作；保存计划不等于交接完成。结束前读接续检查：有待处理结果或独立可执行工作就继续；只有等待中工作时使用宿主有界等待或已验证的原任务定时接续。范围完成、用户暂停、剩余工作全部有具体阻塞，或宿主接续失效且已报告待接手时才结束。暂停优先，结果到达不能自动恢复。

项目 hooks 须经宿主信任并实际加载。`Stop` 检查已登记范围，`SubagentStop` 只记录待处理结果；都不启动生成或重试。服务离线、工具/钩子缺失或连续无进展达到上限时，保留待接手并报告，不宣称后台运行。空闲接续只用宿主官方原任务定时能力，具体接口、状态转换和加载检查按需读接续指南。

## 产物记录

记录实际时长、后端、参数和可得的资源指标，未知值留空。日志只用于定位具体问题，不从一次超时或单次观察推导无证据的性能原因。
