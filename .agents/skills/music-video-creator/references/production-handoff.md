# Panel 与画布交接

新 MV 将下文真实输入及当前歌曲/脚本关联登记到[生产检查](production-checks.md#当前-panel-的提交前检查)。先对当前 Panel 做 readiness，确认仍由 Canvas 创建唯一请求；不把手工绑定表当成服务已读取的输入。

完整 MV 保留一份可审阅的全片创作脚本：音乐窗口、全局人物/美术/文字系统、按时间排序的 Shot、唱词与文字事件、前后镜衔接，以及 Shot 到 Panel 的版本映射。保存于 Canvas 文档节点（如“完整 MV 脚本”）；若主文档在工作区，则画布保存明确版本和可访问引用，不维护两个各自修改的权威稿。局部 prompt 请求只保存所需片段，不强建全片脚本。

各视频节点保存该 Panel 的最终完整 H3 文本及真实素材输入；全片脚本不是一次塞入 H3 的超长提示词。执行用保存并冻结的同版文本，不能在交接时摘要化；修订后更新受影响 Panel 与版本映射，保留已有运行对应的旧版本。用户可以审阅当前脚本和准确输入，已有授权不增加重复确认门。

交给 H3 的单 Panel 事实包含：音乐窗口及当前段作用、生成时长与规格、视频模式、Shot 顺序和切点、主体动作及起止状态、身份/环境/画风锚点、实际媒体引用与用途、逐字歌词或文字、声音来源及后期责任、关键验收点。明确标出镜头是否有人物可见地演唱或说唱；若有，交接对应原曲片段的路径、版本/哈希、源歌曲窗口、`reference_audio` 绑定及 `<Audio N>` 标签。H3 根据模式写最终提示词；MV 保存返回的完整文本，不另行拼接 H3 结构。

每个 Shot 保留 `Vocal Line`、`Typography`、`Visual & Action`、`Camera & Motion`、`Transition Out` 的适用事实；无唱词或无文字时明确省略，不为凑模板补内容。交接具体声音事件、动作链、空间路径、材质变化和可读时刻，不能只交“音乐感强、拼贴、电影感”等标签。

两份原 Skill 的文字/拼贴路线默认由 H3 直接生成完整视觉：准确文字、字形与材质、A/B/C 层关系、人物遮挡、进入/可读/变化/恢复以及跨镜出入方向都交给 H3 写作者。只有已明确独立后期处理的事件才另交后期，不能一律把准确歌词与复杂字效移出生成输入。文字卡只控制包装样式，不能替代人物或场景参考；I2V 只绑定实际首帧，文字卡的视觉要求可整合到首帧和提示词，不虚构额外槽位。[文字方案](../assets/typography_plan.template.md)是创作交接，不是现有渲染 schema。

交接以[文字效果基准](typography-direction.md#效果基准与全片发展)核对逐镜事实：画面主次、声音触发、字形/材质、人物与文字关系、可读恢复和跨镜承接。独立后期修复也须保留所选视觉作用；无法保留时注明差异并交候选，不在交接中静默降低目标。

H3 返回后由调用方对照当前 Panel 核对一次关键事实是否保留：原文、主要层级/遮挡、可读窗口、动作与转场。基础模式把它们写进 `integrated_multimodal_description` 对应 Shot，全参考模式写进 `detailed_description`；不在官方结构外追加独立 Typography 顶层字段，不让编译格式时丢失视觉要求。完整提示词原样保存到 Canvas，执行层不得改成摘要。

生成式上屏文字还须核对图片覆盖：每项准确原文具有已检查的文字图片，并实际出现在所用 I2V 首帧或普通 R2V 图片参考中。记录事件 ID、图片版本、Panel 和槽位；仅有 `related` 资料边、文字计划或通用样式卡不足以证明当前词已传入。I2V 的片内新词未在首帧出现时按视觉资产规则调整模式/镜头，不让提示词补足不存在的参考。缺口只阻塞相关文字镜头，无字镜头不强加此要求。

交接时区分三个时间位置：音乐时间轴保留原歌毫秒位置；成片位置扣除采用窗口起点；H3 切点使用本次生成 Panel 从零开始的相对时间。比如采用窗口从原歌 60 秒开始，原歌 64 秒对应成片第 4 秒；若该 Shot 单独生成，开场仍是 Panel 第 0 秒。源片裁切余量和后期入出点单独记录，不直接拿原歌或成片时间填 H3 切点。

文字事件也转换到 Panel 内时间；有源片前置余量时加上该余量。若原歌事件位于 21.2–22.8 秒，该 Panel 对应原歌 20 秒开始并带 0.5 秒前置余量，生成中事件目标为 1.7–3.3 秒。后期再按实际生成事件位置检查能否与歌曲对齐；多个事件不能只靠移动整段就假定同时同步。这些时间是生成目标，不能单凭提示词证明音频已绑定或镜内同步已成立；实际音频与首帧路径见下表。

明确歌曲在当前 Panel 中的用途：最终沿用主音轨、参考节奏或声线、镜内演唱，或仅供后期对齐。镜内是否演唱与最终声音来自哪里分别决定；仅供后期的歌词不自动成为新增歌声或配乐指令。可见演唱的镜头保留该段逐字唱词和同步要求，音频绑定按下表与[提交前检查](production-checks.md#当前-panel-的提交前检查)核实。`replace` 或 `mix` 按已定声音方案交接，避免把生成的歌声或 BGM 无意叠到主歌曲上。

声音交接同时写明保留/丢弃的层、必须保护的对白或动作窗口、独立素材是否实际可用，以及后期责任。两种全局策略不能表达所有选择性保留或局部避让，按[声音方案与实际能力](finishing-and-review.md#声音方案与实际能力)落实可执行方式；混在同一源轨的歌声、音乐和动作声不能假定已分离。

模式与参考按下表选择。硬切镜头从新机位开始；真实跨 Panel 连续动作等待前段 ACCEPT 和实际尾帧。

## 参考用途到真实输入

原 Skill 给出三类参考分工和逐镜事实，没有完整规定 R2V 槽位与模式选择表。以下是项目执行适配；先读当前能力，不能因模板中出现一个槽名就假定提供方支持。

| 当前镜头的控制需求 | 输入路径 | 交接重点 |
| --- | --- | --- |
| 人物、环境、准确开场文字构图均已确定，且无需可见演唱 | 采用卡 → 图片后端制作单镜首帧 → I2V `first_frame` | 上游卡是首帧来源，视频只消费实际首帧；人物多视图不作为开场画面 |
| 多类参考共同建立新画面，构图可重新组织 | 普通 R2V 的实际图片参考槽 | 分别说明身份、空间、文字样式/准确原文的保留范围；不默认增加首帧引导 |
| 同一片段有首帧之外的新文字事件 | 普通 R2V 绑定相应事件图；无可见演唱时也可拆成独立有字首帧 I2V | 不用通用样式卡假装覆盖新词，不把后续词提前堆到首帧；演唱镜头仍保留歌曲音频输入 |
| 人物可见地演唱或说唱 | R2V `reference_audio` 绑定对应实际歌曲片段；需要精确开场时另加第 0 帧引导 | 必填源版本/哈希、歌曲窗口、真实音频槽与 `<Audio N>`，写唱词、起口及停顿；仍检查实际同步 |
| 无张口演唱的节拍动作需要原歌引导 | 可选普通 R2V 音频槽 | 绑定真实歌曲窗口与源版本，说明节拍用途；不把动作参考当成口型需求 |
| 同一动作跨 Panel 连续 | 前段 ACCEPT 的真实尾帧；无可见演唱可用 I2V，演唱时用带歌曲音频的 R2V 第 0 帧引导 | 继承实际末态；普通换景不建立这种依赖 |
| 无固定身份、精确字形等图片约束的空镜/意象 | T2V | 不声称消费未提供的角色卡、文字卡或音频 |

每个 Panel 在[创作计划](../assets/mv_plan.template.md)保留最小绑定表：实际文件与版本、参考用途、保留/不继承内容、输入槽位、对应 H3 标签。无用途的素材不输入；样式卡已由事件图充分体现时不机械重复绑定。槽位必须与冻结输入一致，不能只建立 `related` 资料边。

例如普通 R2V 实际绑定人物、空间、文字三张图时，`ref_image_0/1/2` 分别对应 `<Picture 1/2/3>`；文字卡不得把自身背景变成场景，人物板不得变成多人或分屏。若实际只绑定两张，就只使用这两张的真实标签，不按模板补号。音频同样依据真实 `ref_audio_N` 映射，不从“有主歌曲”推导生成端已收到它。引用语法由 H3 Skill 维护。

逐镜创作模板的 Vocal Line / Typography / Visual & Action / Camera & Motion / Transition Out 是事实组织方式，不是要原样追加到官方 H3 顶层的另一套协议。编译后核对：全局身份/美术和参考用途仍在，逐镜原文、字形/材质、尺度/深度、动作、可读窗口与音乐触发仍在，真实标签未变；不能只交角色、风格和歌词摘要。

画布操作前读取最新版本、节点与选择。保存仅编辑草稿；确认后服务冻结一次输入并创建请求。已确认本地 Comfy 任务由 worker 执行，MV Agent 不直接提交或重试。图片能力和 Music 3 可用性按当前真实 capability 检查。运行失败、未知或内容未接受时，只处理受影响镜头及依赖。

生成素材可长于最终采用片段。由调用方按[采用版本核对](finishing-and-review.md#采用版本与后期交接)确认当前 review 后，将真实 run、采用文件、哈希、可用动作区间和源片入出点交给后期清单；review 采用派生版本时使用该版本，不能默认取原始输出。候选粗剪明确标为预览，不当作正式接受媒体。
