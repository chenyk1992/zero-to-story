# 说人话

遵守[项目共享生产规则](../../../docs/ai-system-prompt.md)。本 Skill 只处理文本改写工作单元，不承担视频生成、内容验收或监控代理。

把文本从“像模型在表演写作”拉回“像具体人在当前场景下表达”。处理模板感、收束腔、虚假主语、语域漂移和表演性技术腔，同时保住事实、术语、数字、责任主体和原文的抽象层级。它不是敏感词替换器，也不反对专业表达。

## 适用边界

- 用户说“去 AI 味”“说人话”“自然一点”“别像模板”，或要求中文/英文 `chat`、`status`、`docs`、`public-writing` 的风格改写、诊断或标注时使用。
- 逐字翻译、保留原风格、仿官方/品牌 voice、事实校对，以及主要由代码、日志、命令、配置、接口或报错组成的文本，不强套本 Skill。

## 不可变的判断

- 用户当前要求、明确格式和项目术语优先于本 Skill 默认值；用户给出文本和范围后直接交付，不为常规删句、并句、降调或回读重复询问。
- 任何改写都不能新增事实、核心事实、基数、年份、期限、测量结果、实现关系或责任归属；不能把抽象实体擅自具体化，也不能改变谓词方向、完成态、强度或效果类型。
- 原文量化关系有歧义时保留原关系并标出待确认；不替作者修正数量关系。引用、命令、接口名、字段、日志、报错、系统主语和技术术语默认保留。
- 关键词该重复就重复，不用机械同义词轮换。专业文本保持专业，去掉模板化和表演化即可。
- 处理代码上下文、注释、docstring 或 commit message 时保留真实运行行为、适用条件、边界和责任主体，只去姿态词。

## 最小执行顺序

这些是内部判断，不是逐阶段向用户索取确认：

1. 判主场景：`chat`、`status`、`docs` 或 `public-writing`。
2. 划 protected spans，并记录事实、数字与修饰对象、主体与动作/目标、实现关系。
3. 判问题强度 `Tier 1/2/3`，再判改写力度 `minimal/standard/aggressive`。
4. 判结构范围 `structural/bounded/in-place`。
5. 按问题类型读取必要参考；未命中的主题跳过。
6. 输出一个推荐版本；完成一次保真回读，只有仍有明显残留时才追加一次有限 Residual Audit，然后停止。

尺度、场景默认值、无源引用、误杀边界和回读项目见 [改写决策契约](./references/rewrite-contract.md)。

## 单文件兜底

即使只加载 `SKILL.md`，也执行以下最小规则：

- 删开场套话、谄媚、元评论、空总结和收尾腔；把“不是 X，而是 Y”类提示层压回直接表达。
- 无源引用按场景选择 `rewrite-safe` 或 `audit-only`；用户明确要保留原结构时才用 `rewrite-with-placeholder`，不补虚构来源。
- 把商业黑话、表演性技术腔、过度接住和替用户做心理判断压回事实或低承诺表达。
- 缩短翻译腔和长定语链，把名词化还原为动词；不为避重复轮换同义词。
- 没有具体依据时保留原抽象层级或标出缺口，不补工具、产品、能力、指标或实现关系。

## 输出合同

- 默认只给一份可直接使用的推荐版本，不附多版本比稿、逐条点评或完整审稿过程。
- 用户明确“先标问题/只诊断/哪里像 AI”时进入 `annotation mode`：只列最重要的 1–5 个问题，每项写 `问题族`、`触发点`、`建议动作`、`是否建议改写（是/否）`，不偷偷附全文改写。
- `bounded` 长文允许删除整句空话；如删除清单能帮助复核，可随稿简列原句和“不丢信息”的理由，但用户只要成稿时不强制附清单，也不等待确认。`in-place` 一句不删、不并句、不重排，只做句内修改。
- 无源引用按所选模式处理：可以删掉无法独立成立的整条论断、指出缺来源，或显式放置待补来源；不把无证据判断写成已证实事实。`in-place` 使用 `audit-only` 保留整句并提示来源缺口；无源引用规则和第二次回读都不能扩大原 scope。

完整输出字段和高风险例外见 [改写决策契约](./references/rewrite-contract.md)。
