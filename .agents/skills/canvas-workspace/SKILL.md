# 节点画布操作

遵守[项目共享生产规则](../../../guides/ai-system-prompt.md)。页面和宿主使用同一个服务。先读取最新画布、选择和版本，再操作；保存只修改草稿。

## 入口与所需输入

需要目标画布或故事范围，以及要保存的内容、已有素材或待处理请求。工具未加载时，用项目解释器访问同一 HTTP API，读取[操作接口](references/operations.md)中的相应操作。只读取当前操作需要的部分。

| 任务 | 做法 |
| --- | --- |
| 查看或编辑 | 读取版本，按用户要求修改节点；冲突时重读并合并，保留用户最新改动 |
| 整理故事资料 | 章节内容用 `document`，区域用 `section`，图片/视频/语音或音乐生成用 `image`/`video`/`audio`，已有素材用 `asset` |
| 导入明确选定的旧资料 | 按需读[工作空间导入](references/story-workspace.md)，保留来源和既有审片结论 |
| 接手生成 | 区分脚本型与 Agent 型能力，按下节处理 |
| 连续生产 | 仅此时读[接续指南](../../../guides/canvas-continuation.md)并登记当前范围 |

## 保存约定

- 日常先用 `canvas_read(canvas_id)` 的分页目录定位；目录省略长正文和历史，不可把它当完整图覆盖保存。按 `page.next_offset` 和当前 `expected_version` 读下一页，版本变化时重读。需要完整项目数据时显式 `view="full"`。
- 多个镜头用 `canvas_read(canvas_id, node_ids=[...])` 一次精读最多 20 个目标及直接上游；全文和参数原样返回，共享输入只返回一次。按当前版本用一批 `canvas_edit` operations 保存，默认只返回新版本与改动回执；确需全图时设 `full=True`。

- 定稿提示词放目标媒体节点的 `data.prompt`，镜头说明可放 `content`；不新增提示词组件或再次优化文本。创作修改交回对应 Skill。
- 同一媒体节点保存草稿参数、当前 `asset`、实际 `generation_snapshot` 和可选 `history`。编辑草稿不会改变旧成品。不同镜头使用不同节点。
- 生成结果回到原节点；需要并排比较或派生方案时才新增节点。真实尾帧等派生图片放 `derived_outputs` 并按输出端口连接。
- 资料关系用 `related`，不参与生成。首帧与参考素材连接实际输入端口；共享角色图登记一次，供多节点引用。新视频不会自动替换旧末帧文件引用。
- 导入文件不伪造成功运行、原提示词或接受结论。类别、Panel 编号、用途与来源按实际填写；文档来源路径仅用于追溯，画布编辑不反写源文件。删除节点不删除源媒体。

## 已授权运行

页面“确认执行”已授权那次冻结输入，无须再问一次。对话只要求修改、预览或保存时，停在草稿。明确授权执行时，按最新版本确认当前输入并读取创建的请求。

1. **识别能力。** 读取能力说明与待办。脚本型请求由服务处理；`comfy` 视频为 `queued`，由服务启动 [comfy-video-executor](../comfy-video-executor/SKILL.md)，对话不 claim 或重复启动。`comfy-qwen-image` 图片、`comfy-qwen-tts` 语音和 `comfy-minimax-music` 音乐分别由服务启动 [comfy-image-executor](../comfy-image-executor/SKILL.md)、[comfy-tts-executor](../comfy-tts-executor/SKILL.md) 和 [comfy-music-executor](../comfy-music-executor/SKILL.md)，无需 Codex；音乐输入按[Canvas 音乐指南](../../../guides/canvas-music.md)准备。Agent 型请求才进入以下领取步骤。
2. **领取 Agent 任务。** 用当前真实 `host_tools` 调用 `canvas_claim`。能力缺失或抢占失败时报告并保留待办，不先生成。用户明确选择且已接入的 mmx H3 才使用对应执行 Skill。
3. **执行一次。** 严格使用返回的 `execution_snapshot`、素材与参数，提示词原样传入。能力无法表达输入时说明差异；未知状态核实原请求，不重提或换提供方。
4. **回填。** 用 `canvas_complete` 写实际输出路径和媒体类型。宿主无法指定目录时传回真实路径，由服务复制。领取后明确失败写 `failed`，提交结果不能核实写 `unknown`。完成令牌只用于该请求，不写入提示词或媒体元数据。
5. **按用途验收。** 故事媒体或明确要求内容验收的任务，按共享规则记录一次 `ACCEPT/REJECT/INCONCLUSIVE`；普通技术组件只回填技术状态。内容证据不足与提交状态未知是两类问题，不能互相代替。

页面排队不会唤醒空闲 Agent。“待 Agent 接手”不等于已经开始生成。

## 成片与接续

长视频先建立章节/场景索引，将已确认范围按当前制作批次推进，而非把全部提示词和所有历史常驻对话。常规批次先调用 `canvas_next(canvas_id, session_id)`：默认最多 6 个动作，先处理已返回单元和实际媒体；还有工作时计数保留，处理后重读下一批。它只检查当前会话已登记范围，不授权、不生成、不恢复暂停。授权原文或完整单元绑定需要时再读原接续接口。

单次接续范围最多 256 个媒体节点，较大的项目按章节或场景批次登记。处理完的节点可在最新 `revision` 下移出当前范围；仍运行或结果未处理的单元保持在范围内。已有运行和采用结论留在原节点/原 run，不复制到主会话历史。属于具体场景的辅助单元绑定该 `node_id`，避免把所有章节的交接记录积累为全局单元。

主会话负责结果处理，不在已有结果待处理时发起另一个长阻塞调用。独立的长耗时宿主素材任务按现有有界执行单元交接给具备工具的执行者；派发成功后记录真实绑定，主会话使用宿主有界等待并及时处理返回结果。有进行中的画布任务且暂时无动作时，可用 `canvas_next(..., wait_seconds=25)` 等待状态变化；不要为此反复读取全图。项目接口不能中断一个已阻塞的宿主工具，也不独自唤醒空闲宿主；无实际委派/唤醒能力时保留待接手状态。

用户要求完整视频时，使用已接受的 Canvas 输出做顺序连接、裁切、音频和字幕等确定性后期，交付前检查实际最终文件，按需读[视频验收](../zero-to-story/references/video-qc.md)。

独立后期工具不自动继承 Canvas 输入的采用检查。调用方在正式后期交接前读取当前 run.review，核对 ACCEPT、`output_path`、`output_sha256` 与实际文件，采用 review 指向的版本；不能只凭 run_id 或渲染成功认定接受。MV 的音乐版本与声音处理按[后期交接](../music-video-creator/references/finishing-and-review.md)核对。

要由该 run 的 review 采用的裁尾、配声或其他派生版本，保留在原 run 输出目录并对最终实际版本重新验收；旧版本结论不能替代新文件结论。完整项目拼接成片仍按 `projects/<project_id>/final` 产物布局处理。只有最终采用版本 `ACCEPT` 且下游确实需要精确首帧时，才从该 run 提取真实尾帧并登记 `derived_outputs`；不把普通资产边当作接力尾帧。

持续生产先绑定真实宿主会话、明确组件范围和已有授权；实际派发、结果待处理和处理完成按接续指南登记。结果返回后处理并启动下一项 ready 工作；结束前读取接续状态。暂停不自动恢复，持久状态不能独自唤醒宿主。

能力文件只维护交接字段、模式和依赖；具体字段以当前能力与 API 为准。没有已接入执行能力的选项保持禁用。
