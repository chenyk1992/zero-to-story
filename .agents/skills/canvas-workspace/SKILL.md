# 项目节点画布

先遵守[项目共享生产规则](../../../docs/ai-system-prompt.md)。本 Skill 只负责画布读写、已确认任务的领取和实际媒体回填；每次执行是一个有边界的工作单元，不建立监控代理或额外审批层。

页面和当前宿主使用同一个本地服务。先读取当前画布、选择和版本，按用户要求修改；保存配置不会生成媒体。画布工具未加载时，使用项目解释器调用相同 HTTP API，见 [操作接口](references/operations.md)。本 Skill 及能力映射仅在当前项目维护。

## 编辑与查看

- 直接修改节点数据；每次修改带读取到的版本。版本冲突后重新读取，保留用户最新内容，不能整图覆盖。
- 提示词直接保存在图片或视频组件的 data.prompt；修改立即保存为下一次生成草稿，不创建提示词组件或提示词连线。复用文本时复制到目标媒体组件。
- 编剧、分镜、H3 写作和各视频类型的创作复用已有 Skills。本 Skill 只把已确定的内容放入画布，不追加一次提示词优化。
- 已生成组件保留媒体预览和当次 snapshot。用户编辑的是下次生成配置；不能声称旧成品随提示词修改而改变。

## 故事工作空间

以用户指定的一段故事或章节组织一张画布。先读取当前创作源及明确引用的资产，区分故事板描述、定稿提示词、实际生成结果和原有审片结论；已有文件不等于已接受。章节已有素材的归属由已有创作 Skill/资料决定，不重新编写故事或把缺失内容补成已完成。

用 document 保存章节故事与整体故事板，用 section 划分角色或场景区域。图片使用 image，视频使用 video：同一组件包含草稿提示词、参数、当前 asset、实际 generation_snapshot 和可选 history。已有媒体不伪造 succeeded 任务；缺少原提示词时明确未记录。纯素材或音频可使用 asset。配 category、panel_id、description 和来源；镜头故事板可放在视频的 content 中。

生成后在原媒体组件展示成品，不再创建重复的成品或预览组件。旧版本放 history；只有用户需要并排比较或派生方案时再新增媒体组件。真实末帧等派生图片放 derived_outputs，按固定输出端口连接；新视频不自动替换旧末帧的文件引用。不同镜头不能强行归为同一版本。

资料关联使用 related 虚线，不参与生成输入。实际首帧和参考素材使用对应执行端口。共享角色图只登记一次，并连接到使用它的故事板或镜头；不要复制成多份身份资产。

批量整理已有内容时，可使用 [工作空间导入](references/story-workspace.md) 中的小工具。它只导入已明确选定的资料，不扫描整个磁盘，不生成媒体。画布内文档修改保存在 SQLite，来源路径用于追溯，不反向覆盖原创作文件。删除组件只移除画布对象和连线，不删除源媒体。

## 已确认任务的交接

用户点击页面“确认执行”已经授权该运行的固定输入；接手相同请求不用再次询问内容批准。对话只要求修改、预览或保存时，不调用执行接口。

1. 读取待办及能力说明。脚本型能力由服务执行，不从对话再提交；其中用户选择 `comfy` 的视频任务由服务把冻结快照交给项目 [comfy-video-executor](../comfy-video-executor/SKILL.md)，并注入当前 run 的请求标识。Agent 型任务先调用 `canvas_claim`。领取失败时保留 `pending_agent`，报告缺少能力或抢占失败，不能调用生成工具或改写任务状态。
2. 严格消费返回的 `execution_snapshot`；素材路径已经固定。图片和其他能力只使用当前会话实际可调用的 `host_tools`；用户明确选择的已安装代理可排队，但 claim 必须验证目标宿主。mmx H3 只有在用户明确选择且能力可用时才复用 `mmx-h3-video` Skill。claim 缺少相应能力时保留 `pending_agent` 并报告缺口，不调用生成工具或改用替代提供方；已领取后的执行失败才回填失败状态。
3. 只提交一次。已经完整的提示词不再次优化；提供方无法表达已确认输入时停止并说明差异。状态未知时不重提，也不切换后端。
4. 使用 `canvas_complete` 回填真实输出文件与媒体类型。宿主图片不能指定输出目录时，传回实际文件路径，由服务复制到项目媒体位置。故事生产或明确要求内容验收的媒体任务，才查看实际文件、记录可观察的实际末态和实际音频证据，并作一次 `ACCEPT`、`REJECT` 或证据不足时的 `INCONCLUSIVE`；普通文件或技术组件以实际文件和技术完成状态回填，不增加视频内容验收门槛。已领取后的执行失败回填 `failed`；提交结果或内容无法核实则回填 `unknown` 或 `INCONCLUSIVE`，不冒充成功。完成令牌只用于当前领取的请求，不作为提示词或媒体元数据。

页面按钮不会自行唤醒空闲 Agent；显示“待 Agent 接手”时，在当前宿主明确接手。不要将待办描述为已开始生成。

## 完整成片

用户要求把多个 Panel 交付为完整视频时，只使用已经完成内容验收并被接受的 Canvas 实际输出。片段顺序、裁切、音频替换/保留、字幕和交付编码属于确定性媒体处理；它们不能创建新的生成请求、改变已接受片段或成为隐藏的提供方入口。处理完成后回看实际最终文件，核对可播放性、片段顺序、接缝、声音、字幕与同步；无法完成的视听检查如实报告。

## 持续生产的接续

需要从一个工作单元继续到下一单元时，遵守[接续指南](../../../docs/canvas-continuation.md)：通过 `canvas_continuation_configure` 绑定当前真实宿主会话、明确组件范围和已有授权。只有宿主实际派发成功后才用 `canvas_continuation_unit` 登记子代理与工作单元；结果返回先记录待处理，完成原任务核实和后续交接后再记录处理结论。读取 `canvas_continuation_read` 确认下一步；不要仅保存计划就结束回复。

接续工具不自动确认生成、替代内容验收或授予权限。未配置的会话无动作；用户暂停/中断后保持暂停；失败、未知和未通过验收的镜头只阻塞相关依赖。Codex 项目 hooks 要经过宿主信任才能执行，持久状态本身不能唤醒空闲会话。需要定时接续时使用宿主原任务的官方能力，不能新建模型监控代理或自写后台发提示词循环。

能力文件只描述交接字段、可选模式与依赖，不复制外部 Skill 的提示词规则、凭据流程或 CLI 协议。没有已接入执行能力的选项保持禁用。
