# Agent 型媒体的执行结果交接

本页只适用于已由 Canvas 确认、领取的宿主媒体请求；不创建画布外的生成入口，不改变脚本型 worker、未知占用或恢复权限。原运行、冻结输入和生产状态仍以 Canvas 为准。

## 一项生成，一项持久回填

1. 领取后核对 `run_id`、`request_id`、节点和 `execution_snapshot`。调用生成工具前，用 `canvas_progress` 记录 `stage=submit` 和该项调用事实；记录失败则不调用生成。
2. 每项只调用一次真实宿主生成工具，使用原冻结输入。不能把多个长耗时生成放在一个提前抛错的 `Promise.all` 中。宿主无法在并行中保证每项独立落盘与回填时，逐项执行。`Promise.allSettled` 本身也不等于持久保存。
3. 成功返回后立即保留真实媒体文件及可得的提供方回执。用 `canvas_progress(stage=collection)` 写 `remote_finished=true`、实际 `outputs` 路径及可得的提供方请求编号。只有服务已收到该证据后，才继续 `canvas_complete(status=succeeded)`；回填完成再开始下一项。不要打印图片 Base64 或完成令牌。
4. 如果保存进度或回填发生异常，保留宿主已返回的实际路径，在本项目原 run 输出目录保存无令牌的交接证据，核对原 run 后只继续回收/回填同一结果。不得再次调用生成工具，也不得把回填异常改写成提供方失败。若服务已持久记录 `remote_finished`，按现有回收入口处理同一结果；缺少证据时保留未知。

异常必须在所属阶段独立捕获：生成调用的异常与 `progress/complete` 的异常不能共用一个将所有情况写为失败的外层 catch。临时证据只是原调用证据，不是新的生产状态机或旁路自动恢复机制。

生成领取与审片领取是两个独立令牌。调用 `canvas_claim` 或 `canvas_claim_review` 后立即将整个领取响应保留在当前执行上下文，再使用其对应令牌；不能只打印响应后依赖下一段代码中的未保存变量，也不能拿生成令牌提交审片。审片校验失败时保留原审片令牌修正本次请求，不再次 claim。上下文丢失但原领取工具响应仍在本会话记录时，只找回该响应中的原令牌继续同一请求，不猜令牌、不读取数据库、不换领取者；不打印令牌或写入媒体证据。

## 错误如何归属

| 实际证据 | 回填 |
| --- | --- |
| 单项明确返回终止拒绝，例如该项 `moderation_blocked` | 仅该 run 为 `failed`；保留原始错误、审核阶段/类别和可得请求编号，不推测细分原因，不自动重试 |
| 已提交后超时、中断、连接断开、回执丢失或聚合错误无法归属 | `unknown`；只核实原调用，不以没有文件推断失败 |
| 宿主成功返回文件，但 Canvas 回收/校验失败 | 记录 `remote_finished` 和实际文件证据，按同一结果回收处理；不生成第二份 |
| 一项失败，另一项结果未返回 | 分别记录；不能把第一项错误复制成另一项已确认失败 |

`provider_task_id` 只填真实生成任务编号；服务诊断用的 request ID 写在 evidence 中，不能冒充可查询任务编号。令牌只用于对应接口，不写进创作资料。

## 新尝试与历史更正

新制作尝试须有明确的用户授权，读取最新输入并创建独立请求；不复用原请求编号伪装为原结果恢复。保留原媒体、错误和“提供方结果未核实”的事实，记录新尝试与旧 run 的关联。历史终态不能通过普通 complete 改写；可在节点/工作空间说明中追加事实更正，或用 attention 标注本地停止跟进。attention 不证明远端失败，不释放未知占用。若原任务仍受未知占用保护，当前工具不允许绕过。
