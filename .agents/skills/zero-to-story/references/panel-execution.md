# Panel 交接与执行

共同的角色、Panel ready、单工作单元、实际末态/音频验收和授权规则见[项目共享生产规则](../../../../docs/ai-system-prompt.md)。本文件描述 H3 创作事实进入 Canvas、固定快照、实际媒体回填与审片的唯一生产路线。

本参考只在 Panel 已有确认的故事板、模式和素材关系，需要写 H3 handoff、准备 Canvas 节点或执行/成片处理时读取。Canvas 操作由 [canvas-workspace](../../canvas-workspace/SKILL.md) 负责；实际内容与最终检查以 [最小视频接受检查](video-qc.md) 为准。

## STEP 4：交给 H3 提示词作者

每次只处理一个 Panel，并读取 `$h3-prompt-writing` 对应模式的官方 reference。提供已经确认的创作事实，不自写 H3 提示词草稿：

- Panel 时长、画幅、Medium Lock、Style Brief 和节奏意图。
- 六 Beat 到 Camera Setup 的映射；每个 Setup 的构图、机位、轴线、朝向、目标/视线、屏幕运动、运镜动机及起止、动作完成依据、声音和锁定末态。
- 逐字对白、说话人、语言、画外音状态，以及台词字幕和场景文字的制作责任。
- 推荐 operation、精确首/尾帧要求、连续或硬切关系。
- 最小 `runtime_input_keys` 与素材用途；R2V 的已锁定 `storyboard_layout` 和按阅读顺序排列的格子到 Beat/Setup 映射。
- P002 起的零时长边界锚点和唯一 transition ownership。

H3 skill 负责字段、标签、镜头时间、对白语法和最终英文措辞。它不能静默换模式、丢弃必需素材、重排对白或改变已批准时长。R2V 分镜板作为一张图片和一个 fixed reference 处理；提示词中说明阅读顺序与内容，但不附加不存在的独立格子图片。需要修改时重新交给 H3 skill，不在本 Skill 内手工修补。最终提示词符合已确认的创作事实和用户指定的审核阶段后，逐字保存到目标 Canvas 视频节点，不创建第二套提示词状态。

## STEP 5：每个 Panel 准备并确认一个 Canvas 快照

每个 Panel 使用一个独立 Canvas video 节点，只表达当前 Clip。保存以下固定输入：稳定 `project_id` 与 Panel 标识、精确时长、画幅、模式、最终 H3 提示词、最小素材引用、Canvas 能力要求的参数、音频/字幕后期责任和验收要求。不要把所有 Panel 或跨 Panel 依赖塞进一个视频节点。

从故事板和蓝图 `user_constraints` 继承用户已选的 `megapixels`、`sampler_profile`、`steps`；后续 Panel 不重复询问、不临时改步数或混用模式。采样参数属于 Canvas 节点配置，不塞进 H3 提示词。用户明确变更后，更新项目规格和受影响节点草稿；已经冻结的请求仍保留原输入。

I2VA 只绑定 `first_frame`；FL2VA 绑定 `first_frame` 与 `last_frame`；R2V 按资产计划绑定整张 `storyboard_board.<panel>` 或明确用途的普通参考；T2V 不带媒体输入。素材路径由 Canvas 保存与确认过程固定，不把 ComfyUI 节点、模型路径或内部素材 ID写进创作文件。

保存节点只是编辑。只有页面确认或对话明确授权后，Canvas 服务才冻结当前 `execution_snapshot`；已确认快照由服务按所选能力提交一次。用户选择 `comfy` 时，服务调用 [comfy-video-executor](../../comfy-video-executor/SKILL.md)，上游 Skill 不直接运行 comfy-cli。

## 最小状态与版本

只保留有助于继续创作的状态：故事板/蓝图为草稿或已确认，角色与视觉资产为未生成、待确认或已确认，Canvas 节点为草稿、已确认、执行中或已有实际结果；内容判断为 `ACCEPT`、`REJECT` 或 `INCONCLUSIVE`，尚未检查时留空，执行错误另记。用户修改故事板、时长、画幅、角色锚点、引用、模式或 H3 提示词时，只更新受影响节点的下一次生成草稿，不改写旧快照或已接受媒体。每次继续前读取最新画布和创作文件，不从旧对话补写已变更内容。

用户明确授予一定范围内的持续执行授权时，记录其原话、项目和范围；这不默认覆盖扩大制作范围、改变已选生成参数、增加收费/外部服务或未授权的数据操作。每个实际请求仍由 Canvas 服务冻结精确快照并只提交一次。单纯沉默、等待超时或未知状态不建立授权，也不能触发重提。

## STEP 6：逐 Panel 隔离串行

每个 Panel 使用一个短生命周期、相互隔离的执行单元，视频提交保持串行；只消费当前 Canvas `execution_snapshot`，不传完整故事、前序日志或内部状态。只有当前 Panel 依赖上一 Panel 的真实状态时才等待前段 `ACCEPT`：

```text
保存当前 Canvas 节点草稿
→ 页面确认或对话明确授权，冻结 execution_snapshot
→ Canvas 服务按所选能力提交一次
→ 实际媒体回填原节点
→ ACCEPT / REJECT / INCONCLUSIVE
→ ACCEPT 且下一 Panel 需要时：提取真实尾帧并绑定
```

可以并行做资料读取、H3 提示词准备、独立资产准备和普通代码工作，但不能并行提交视频 Panel。下一模式需要精确首帧时，由调用方在上一 Panel `ACCEPT` 后从实际接受视频提取尾帧，导入 Canvas 并绑定为下一节点的 `first_frame`；不能用文字描述或虚构路径代替真实尾帧。没有下游用途时不做多余提取。

执行单元按 [最小视频接受检查](video-qc.md) 查看实际文件，对关键身份、动作因果、实际完成状态、实际末态、实际音频证据和相邻衔接作出 `ACCEPT`、`REJECT` 或证据不足时的 `INCONCLUSIVE`。执行技术成功不等于内容 ACCEPT；片段级后期也纳入这次检查。拒绝、证据不足、生成错误、超时或素材不可用时暂停受影响任务，不盲目重试、不把失败候选登记为正式产物，也不另写恢复侧车。

## STEP 7：一次最终成片处理

全部 Panel `ACCEPT` 后，如用户要求完整视频，只对这些已接受的 Canvas 输出做确定性媒体处理；按计划连接片段、处理音频和字幕，不调用生成模型。实际交付文件按 [最终成片检查](video-qc.md#最终成片) 核对。发现具体问题时报告最小修正范围；未完成的观看或听审项目如实报告，不以轨道存在代替通过。

## 停止与继续

故事板、蓝图或 Canvas 节点草稿的可逆问题，在当前授权范围内按具体报错定点修复和复核；同一问题无新依据不重复修复。生成错误、硬件/素材功能错误、引用模式不兼容、授权缺失、`REJECT` 和 `INCONCLUSIVE` 都暂停受影响 Panel。只有用户新指令、修正后的输入或新的已确认快照满足继续条件后，才重新发起受影响 Panel；原请求状态未知时先核对，不重提。
