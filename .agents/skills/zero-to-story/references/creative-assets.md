# 角色与视觉控制资产规范

## 代表镜头与身份风险

只有采用未经验证的制作方式、且实际生成授权涵盖试验时，才用一个与当前风险相关的镜头试点；普通创作不增加试片。新人物露脸、从背影转人脸、多人同框或关键接触可作为选择依据。身份信息无法由首帧完整提供时，评估 R2V 并绑定实际角色参考；首帧已包含所需身份和空间信息时，I2V 仍可使用。

参考图会同时传递身份与材质风格。人物卡将皮肤、光线或线条风格带偏时，调整参考图或明确其用途，不靠不断叠加否定词修补。大幅转向或复杂空间变化先判断是否应切镜；每个镜头明确轴线、视线对象、道具归属、接触关系和动作完成位置。

跨章节素材使用稳定且有项目范围的资产 ID；同名 Panel 不共用可覆盖的输出路径。画布 `related` 仅供资料关联，身份参考必须连到实际输入端口；确认时核对模型真正收到的素材及其顺序。

共同的角色、Panel ready、资产依赖和实际验收规则见[项目共享生产规则](../../../../guides/ai-system-prompt.md)。本文只规定角色和视觉控制资产的选择与检查。

## 角色设定图

### 目标

为每个需要视频身份一致性的主要角色制作独立角色卡。角色卡负责身份、体型、发型、服饰和关键道具，不承担剧情构图。

从已批准的 `storyboard_brief.md` 逐字提取角色身份锚点。不要混入人物小传、剧情秘密或镜头安排。

### 提示词模板

使用 [单角色设定图 Prompt 模板](../assets/character_card_prompt.template.md)。只替换占位字段，不在 reference 和项目文档中复制维护另一版模板。

角色卡与其他资产统一在[视觉可用性检查](#视觉可用性检查与提示词诊断)做一次用途判断，不在此重复检查或自动重做。

## 人物与场景文本锚点

`storyboard_brief.md` 中的文本锚点是跨模式复用的最小视觉描述，不是每个镜头重新发挥的提示词。人物文本锚点只包含稳定的年龄段、脸型、发型、体型、服装主色和标志性道具；场景文本锚点只包含稳定的空间结构、材质、主色、光源、时间天气和辨识物。雨湿、尘土、伤势、手持物等随剧情变化的状态放在连续性账本。

- T2V 没有视觉首帧时，必须把当前镜头真正可见的人物/场景文本锚点写入提示词；一次性空镜只需要场景锚点。
- I2V 以已确认首帧为主要身份和环境参照，只补充首帧无法表达的稳定约束，不引入与首帧冲突的第二套描述。
- 反复出现且空间布局重要的场景，按需生成并确认一张彩色场景关键帧，供新场景 I2V 或必要的 R2V 使用；一次性空镜不强制创建场景卡。
- 不要把角色卡、R2V 分镜板和场景关键帧无条件同时塞给视频模型；分镜板在生成时可以吸收必要的身份、环境和构图信息，进入 H3 时默认只保留这张板作为视觉参考，其他素材必须有不可替代且不重复的用途。

复用视觉参考时，区分稳定身份/布局与图中暂时的剧情状态。旧参考里的持物、姿态、门窗和灯光可能把新段拉回动作起点；存在影响当前剧情的冲突时，应按当前控制方式准备相符参考或调整机位，不只用文字要求模型忽略矛盾。连续接力也应在人物重新显露或合理换镜处核对原角色锚点，避免沿用逐段漂移的脸或服装；无需固定间隔重做角色图。

真实尾帧只承载其中可见的信息，不是完整身份记忆。从手部、背影或物件特写重新显露面部时，先检查输入是否仍有足够的身份依据；在故事板阶段选择保留身份信息的结尾、合适的已批准关键帧或明确切镜的参考控制。不得向 I2V 追加角色卡来绕过唯一首帧约束，也不承诺文字锚点能恢复不可见的脸。实际面部重现后的身份检查纳入调用方的一次 Panel 接受。

## 逐 Panel 视觉资产路由

优化优先级固定为：先删去视频模式不需要的资产，再按每项资产的实际用途做二元可用性检查，最后才对剩余生成任务做依赖感知并行。并发数量不是目标，不得为了填满并发槽位生成相似参考。

STEP 1 先在 `storyboard_brief.md` 和 `creative_blueprint.json` 中锁定每个 Panel 的 operation，再选择 `visual_asset_policy`。STEP 3 只物化该计划，不重新决定模式。

| Policy | STEP 3 动作 | 常见 operation | 运行时用途 |
|---|---|---|---|
| `none` | 不调用图片模型；使用文本或等待上一 Clip 真实尾帧 | T2V、同场接力 I2V | 由 `runtime_input_keys` 显式决定 |
| `storyboard_board` | 按 STEP 1 锁定的布局一次生成或复用一张自包含电影画面分镜板 | R2V | 以 `storyboard_board.<panel>` 作为一个 fixed reference |
| `reference_assets` | 复用已明确选择、各有用途的 typed 图片、视频或声音参考，如场景视频、开场构图、人物正面或声音样本 | R2V | 按 `kind` 绑定独立 `reference_image`、`reference_video` 或 `reference_audio` 槽位；不视作精确首帧、不强制分镜板 |
| `scene_keyframe` | 生成或复用一张与成片画幅一致的彩色场景/首帧关键帧 | 新场景 I2V | I2V 时它必须是唯一精确首帧 |
| `last_frame` | 生成一张与成片画幅一致的目标尾帧 | FL2V | 与精确首帧成对传入，不附加分镜板 |

`runtime_input_keys` 是会真正传给视频模型的最小素材集。`planning_only_asset_keys` 只供导演审阅、历史对照或人工说明，默认不在 STEP 3 物化，禁止绑定为 H3/Canvas 参考。R2V 可以选择 `storyboard_board` 或 `reference_assets`；若选择分镜板，必须在 STEP 1 以 `storyboard_board` 和明确布局重新纳入当前计划。资产不能反向决定 operation。

### 当前 Panel 的素材检查

只检查当前 Panel 实际要用的素材，不建立全局资产先行门禁，也不阻塞素材已齐全的独立 Panel。把结论落在现有计划和 Canvas 输入中：

| 项目 | 核对内容与责任 |
| --- | --- |
| 存在 | Canvas readiness 核对实际文件、已接受尾帧依赖和当前能力输入是否可用；T2V 没有视觉参考也可以成立。 |
| 用途 | 创作者说明这项素材为何服务当前模式，例如精确首帧、身份、场景布局或声音参考；`planning_only` 不能充当运行时素材。 |
| 绑定 | Canvas 快照的端口和槽位必须与计划一致；创作者再核对图中人物、状态和构图是否真能承担所声明用途，不能仅凭 `related` 关联推断。 |
| 版本 | 创作者确认引用的是计划中的资产版本；真实续接使用已 `ACCEPT` 的源版本。Canvas 确认时冻结实际输入，后续替换素材按新快照处理。 |

这四项分别由 Canvas 就绪检查、创作者的导演判断和既有确认流程承担，不新增表单、批准状态或生成任务。等待另一个 Panel 的角色图时，当前 Panel 若自身 `runtime_input_keys` 已齐全且没有真实依赖，仍可按原计划推进。

## R2V 自包含可变网格分镜板

### STEP 1 锁定布局

只有选择 `visual_asset_policy: "storyboard_board"` 的 R2V Panel 才需要在生成图片前写明 `storyboard_layout`。布局使用规范的 `rowsxcolumns` 小写字符串，例如 `1x2`、`2x2`、`2x3`；行数乘列数必须为 2–6。选择 `reference_assets` 时不强制生成分镜板；这里描述的是分镜板网格，不替代成片的 `aspect_ratio`。

每个 Panel 只有一个 `storyboard_board.<panel>` asset key 和一张图片。STEP 3 直接按锁定布局生成整张分镜板，不先生成单格图片，不下载后拼接，也不把单格作为额外 H3 引用。板内格子固定按从左到右、从上到下读取；`storyboard_brief.md` 和图片提示词写清每格对应的 Beat、Camera Setup 与控制用途。

### 按信息增量选择格子

六个 Beat 仍完整保存在故事板中，但网格格数不与 Beat 数机械绑定。一格可以代表同一 Camera Setup 下的多个 Beat；只有需要表达以下新增信息时才增加格子：

- 新 Camera Setup、明确硬切或新的空间关系；
- 新人物关系、关键站位、视线或构图；
- 关键动作转折、手部状态或道具归属变化；
- 需要 R2V 明确理解的完成状态。

同机位、同人物关系、同道具状态且只发生轻微表情或位移变化的时刻不占新格。若一个画面已经足够控制视频，可在规划阶段选择 I2V/`scene_keyframe`；用户明确选择 R2V 时可用普通参考，不为分镜板机械补格，也不在执行阶段改模式。布局一旦随创作计划获批，STEP 3 不临时改格数；需要改变布局时先回到 STEP 1 更新蓝图并重新确认。

### 一次生成整张板

一次图片生成只使用整张板承担一致性用途所需的信息：

1. 已确认的 `Medium Lock` 和 `Style Brief`；
2. 已锁定的 `storyboard_layout`，以及每格覆盖的 Beat、Camera Setup、构图和关键状态；
3. 完整的人物与场景文本锚点；
4. 图片模型支持参考图时，分镜板确实需要锁定身份的角色卡；
5. 图片模型支持参考图时，分镜板确实需要锁定空间的场景关键帧；
6. P002 起需要承接时的已完成边界状态；模型支持参考图时，才附加确有用途的最近批准视觉资产。

分镜板 Prompt 必须自包含：图片参考是可选增强，不得承载文字锚点中没有写出的唯一剧情或辨识信息。模型支持参考图时，角色卡负责增强身份一致性，场景关键帧负责增强空间和光线一致性；模型不支持参考图时，直接省略这些输入，以文本锚点中的少量稳定辨识特征替代，不得虚构模型已经读取图片，也不因此更改布局或格位语义。板内格子始终负责构图、姿态、道具状态和镜头关系。生成完成后，H3 默认只接收整张板；只有分镜板确实无法承载的声音、身份或其他控制信息，才额外加入一个有明确用途的参考。

### 分镜板视觉标准

分镜板统一采用与目标成片一致的电影画面风格，保留必要的人物形象、五官和衣着等。各格明确必要的构图、人物关系和关键动作状态，保持角色与场景外观一致；中间运动、自然表演和声音由视频生成完成。

### 画布选择

根据成片画幅、`storyboard_layout` 和图片模型支持的规格，选择一张正常的标准画布；整张板的像素预算不随格数成倍增加。目标成片画幅只用于指导各格的镜头构图与安全区，分镜板本身不是精确首帧。整张板由图片模型按最终网格一次输出；不要先生成大尺寸独立帧再拼成更大的合成图。

## 分镜板提示词

使用 [R2V 可变网格分镜板 Prompt 模板](../assets/storyboard_board_prompt.template.md)，一次写完网格规格和所有格子的静态可见内容。每格只承担一个主要控制用途；不要把音频说明、完整台词、完整视频时间线或同一 Setup 的所有细微动作塞进图片提示词。

## 单帧场景与尾帧关键图

`scene_keyframe` 和 `last_frame` 使用 [单帧视觉控制图 Prompt 模板](../assets/visual_keyframe_prompt.template.md)。输出必须是一张独立成片帧，与目标画幅一致；禁止网格、多画面、分镜线、标题、标签和箭头。

- `scene_keyframe` 只锁定开场需要的空间布局、角色身份、光线、机位和动作起点，不在一张图里绘制整段动作。
- `last_frame` 只画 Panel 结束后的已完成可见状态，精确匹配尾帧硬约束。不画运动轨迹、前后对比、正在发生的中间动作或对白气泡。
- 若单帧本身不能同时容纳全部身份与道具约束，回到 STEP 1 简化控制目标或重选 operation，不把分镜板强行加进 I2V/FL2V。

## 依赖感知生成

生成前为每项待生成资产写出直接依赖即可，不建立额外调度文件或状态系统：

- 角色卡和无需场景图的独立资产是根任务；
- 依赖同一组已确认角色卡、场景关键帧或文本锚点，且彼此不引用的不同 Panel 分镜板或其他资产，可以在当前工具并发额度内有限并行；
- 明确把另一张待生成图片作为参考的资产，必须等该依赖确认后再生成；
- 同一 R2V Panel 的整张分镜板是一个原子任务，板内格子不拆分、不并行、不单独 QC；
- 失败只阻断依赖它的后续资产，不触发自动重试；由调用方修正提示词、参考组合或资产计划后再决定是否重新生成。

当前 Panel 自己所需的运行时资产确认后即可进入 H3 提示词和 Canvas 交接阶段；其他独立 Panel 的资产不构成全局阻塞。视频 Panel 的真实尾帧接力仍严格串行，不属于本节并行范围。

## 跨镜头与跨帧连续性

在故事板已有的 Beat/Setup 字段记录会影响动作或接续的状态；无变化时沿用前态，不复制整表。以下是可选观察维度：

| 项目 | 与当前动作有关时记录 |
|---|---|
| 人物 | 左/中/右，前/中/远景，朝向，姿势，视线 |
| 双手 | 左右手分别空闲、持物、接触或遮挡什么 |
| 道具 | 数量、所有者、位置、连接状态、是否可见 |
| 场景 | 门窗开合、灯光状态、天气、背景人物数量 |
| 镜头 / Setup | 轴线哪一侧、景别、机位高度、摄影机所在位置与朝向、下镜是否切轴 |
| 画面关系 | 人物在画面中的位置与朝向、面对的目标、视线落点、屏幕运动方向、与前一 Beat 是同镜继续还是 cut |

让相邻 Beat 的锁定末态成为下一 Beat 的初始状态；同一 Setup 按已计划的摄影机轨迹、人物走位和转身连续推进，不无故重置机位、轴线或朝向。计划内运动不等于新增切镜。发生交接时按“接近 → 接触 → 双方共同持有 → 原持有者释放 → 新持有者收稳”描述可见过程，可跨相邻 Beat 表达，不强制每一步独占一个 Beat。跨 Panel 时先登记 `transition ownership`：共享边界动作只能归前段或后段，后一段的边界锚点只保留完成后的状态，首个有效新 Beat 从该状态推进，不能倒带、重置或重演。

生成 R2V 分镜板时，以故事板中的边界末态和最近的批准资产为共同事实来源。板内相邻格不要求像素级复制，但关键景别、人物站位、朝向、手部、道具和已完成末态不能互相矛盾，也不要把边界动作画成正在发生。不为填满网格重复同一画面或补生无信息的中间状态。

跨 Panel 生成方式按镜头关系选择：同场连续接力优先 I2VA，以上一段真实尾帧锁定当前段首帧；只有同时需要精确首帧和尾帧才用 FL2VA；需要一张多格分镜板承载强一致性控制或明确硬切时才用 R2V。R2V 分镜板自身使用 `placement: "fixed"` 并占一个明确的 `ref_image_N` 槽位；它约束身份、构图和状态关系，不是精确首帧锁。只有用途明确且分镜板无法承载的非分镜素材，才可另外占用参考槽位。

## 视觉可用性检查与提示词诊断

资产生成后只做一次用途判断。以下项目按当前资产要求选用，不相关项不填；资产可用不代替视频验收：

- 角色卡：角色身份、服饰/关键道具、全身视图和画风可用，且没有明显伪文字或额外角色。
- R2V 分镜板：行列和格数与 `storyboard_layout` 一致，阅读顺序明确；每格能表达计划中的构图、人物关系、关键动作或道具状态，格子之间没有会误导视频的身份或状态冲突。
- 单帧关键图：只有一张独立成片画面，画幅、主体、空间和目标状态与计划相符，没有网格、标题、伪文字或水印。
- 所有资产：与已确认的 Medium Lock、角色/场景锚点及 operation 用途相符。

只有以下功能错误才阻断当前资产：关键主体缺失或身份错误、关键道具/动作状态错误、画面无法承担声明用途，或参考之间存在足以误导视频的矛盾。轻微五官细节、衣纹、材质、光影或构图差异不影响身份辨识、关键关系和目标成片风格时直接接受，不逐格打分，不为这些差异返工。

网格规格、格数或阅读顺序错误，以及某格缺失关键状态，属于分镜板功能错误。说明问题并准备整板输入修正；重新生成须在授权范围内确认新快照，不自动重做或退回逐格拼接。保留历史媒体，但不把失败候选登记为正式产物。

## 运镜词汇与摄影动作词典

> 分镜板中的格子只是选出的可见时刻。本词典用于说明摄影机与主体的实际关系，不是质量排名，也不是 H3 必须逐字使用的控制语法；最终提示词表达由 h3-prompt-writing 负责。

### 运镜

| 词汇 | 含义 | 适用场景 |
|---|---|---|
| `固定` / `fixed` | 摄影机不动 | 静态人物对话、关键帧建立空间 |
| `handheld shake` | 手持微晃 | 真实感、纪实、紧迫、跟拍人物 |
| `dolly in` / `dolly out` | 推/拉（移动机位） | 逼近主体或拉远建立空间，景别变化 |
| `push-in` / `pull-out` | 向主体推近 / 离主体拉远 | 主体可静止或运动；写清摄影机路径，不与变焦混淆 |
| `truck left` / `truck right` | 水平平移 | 跟主体侧向移动、扫视环境 |
| `pan left` / `pan right` | 水平摇（原地转） | 揭示空间或跟随横向运动；摄影机位置不变，不要求人物静止 |
| `tilt up` / `tilt down` | 俯仰 | 揭示高度、强调细节 |
| `pedestal up` / `pedestal down` | 整体升降 | 改变视平线 |
| `zoom in` / `zoom out` | 改变焦距与视场 | 单独变焦不移动机位，不等同推轨造成的空间透视变化；按叙事或风格意图选用 |
| `crane up` / `crane down` | 摇臂 | 大范围上升下降（开场/收尾常用） |
| `环绕` / `orbit` | 摄影机绕主体作弧线移动 | 写明主体、绕行方向、范围、起止构图与视线目标；侧移加摇镜不是完整绕行路径的等价定义 |
| `tracking shot` | 移动摄影机跟随或伴随动作 | 写明跟随对象、前/后/侧方关系、方向与稳定性；不必带手持晃动 |

### 景别

| 词汇 | 范围 | 用途 |
|---|---|---|
| `extreme close-up`（极特写） | 眼睛、手、道具细节 | 强调情绪或关键物件 |
| `close-up`（特写） | 脸、头部 | 情绪反应、对话 |
| `medium close-up`（中近景） | 头肩到胸 | 人物对话、反应 |
| `medium shot`（中景） | 通常腰部以上 | 手势、人物互动与表情 |
| `medium long shot`（中远景 / 膝上景） | 通常膝部以上 | 保留较完整的身体动作和站位关系 |
| `full shot`（全景） | 全身 | 人物与场景关系 |
| `wide shot`（远景） | 全身 + 大场景 | 建立空间、群戏 |
| `establishing shot`（建立镜头） | 建立空间关系的功能，不是固定景别 | 常用远景，也可用清楚的连续运动建立位置关系 |

### 切镜风格

| 词汇 | 含义 |
|---|---|
| `cut` | 普通硬切（默认） |
| `fade` / `dissolve` | 叠化视觉意图（仅由单个 Clip 或已批准派生素材实现） |
| `rhythmic cut` | 随节奏卡点切镜（与 BGM/MV 场景） |
| `jump cut` | 相近构图中的时间/动作跳跃，不等于所有快速剪辑 |
| `match cut` | 以动作、构图等相似关系连接镜头，可连续也可跨时空 |

### 用法约定

- 故事板 Camera Setup 行的“运镜”列优先用本表的明确术语，并写出叙事作用与起止；其他必要拍法用无歧义的空间描述，不用“跟拍”“推进”等泛词作为唯一描述。运动方式和景别按画幅、表演与用途选择，不把单一技巧视为天然高级或廉价。
- 分镜板本身不需要写出运镜词，但按阅读顺序排列的格子应符合运镜逻辑（如 `dolly in` 后的格子中人物占据画面更大）。
- 跨 Panel 末态承接时，写清运镜方向（"上镜结束在 `tilt up` 末态"），下 Panel 第一镜的运镜要能合理接续。
- 完整成片只对已接受的 Canvas 输出做确定性媒体处理；`match cut` 仍是剪辑关系。若需要淡化、黑场或声音桥接，必须由单个 Clip 完整持有，或在最终时间线中以已确认的确定性处理实现，不触发生成模型。
