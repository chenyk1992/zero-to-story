# 影视故事的分阶段协作

仅用于 zero-to-story 主责的影视故事，交付到用户要求的阶段。整部作品通常留在开始时选择的 Codex、Claude Code 或 Pi 内；不设计跨宿主接管。复用当前创作主源、Canvas 和[接续记录](../../../../guides/canvas-continuation.md)，不新增生成队列、预算模块或常驻调度服务。

## 角色与材料

主会话保留用户入口和最终责任，具体制作按故事、分镜/资产、片段、后期分配给有界执行者。一个阶段完成后用成果交接，避免所有执行者继承完整对话；简单局部任务可以直接完成。

| 角色 | 本次输入 | 返回与写入边界 |
| --- | --- | --- |
| 主做 | 当前阶段目标、采用主源/版本、必要素材、明确要求与授权 | 完整受托成果、改动与未知项；只编辑分配范围，不改变锁定事实 |
| 审核：故事盲读 | 当前可阅读故事正文、中性问题 | 先复述理解，再列位置/证据/疑点；不读导演解释、不改文件 |
| 审核：生成前 | 本 Panel 分镜、完整提示词、实际输入图/音频、相关设定与模式 | 指出图文/动作/身份冲突及影响；不改文件、不生成 |
| 审核：成片盲审 | 当前最终媒体，包含观众实际能看到的标题字幕 | 理解、注意力/情绪变化、具体时间与未知；不读剧本、需求清单或旧评价 |
| 监督 | 有来源的明确要求、当前决定、本阶段成果与变化 | 已落实/遗漏/偏离的依据；不把制作建议变成用户要求，不改作品 |
| 代理 | 具体分歧、相关证据、可选改法、明确偏好及授权 | 决定、理由和影响范围；不直接改作品或提交生成 |

审核与监督只返回结果，由调用方保存。工具限制以实际宿主能力为准；“只读”提示词不代表文件系统强隔离。代理可裁决既定目标内的镜头、节奏和局部表达；改变核心故事、结局、已确认风格或用户明确要求，交回用户。事实错误不能用审美偏好豁免，审美建议也不能自动成为返工命令。

## 执行顺序

1. **故事**：主做形成可阅读场景稿，用新的无历史实例做一次故事盲读。主做比较读者理解与意图，修正影响理解的问题；悬念和开放结尾允许保持未知。进入分镜前处理明确问题，已通过且未改动的正文不重复审。
2. **分镜与资产**：按[导演提示词](story-collaboration-prompts.md#分镜与视觉设计)明确注意力、动作起止与画面/声音关系。先用低成本文字或简化构图解决关键关系，再准备模式实际需要的资产；不用强制首尾帧替代模式判断。
3. **生成前**：审核当前 Panel 的完整实际输入，发现关键矛盾先交主做修订；返回无关键冲突后，在已有授权内走 Canvas。模板和审核结论本身不授权生成。输入变动只检查受影响项，未变的共用设定可复用证据。
4. **阶段交接**：监督核对本阶段成果及需求变化；没有分歧就继续。有争议的局部表达交代理处理一次，仍缺关键依据才提请用户，不让角色无限循环争论。
5. **成片**：后期形成实际最终版本后先盲审，再结合要求核对与必要视听证据作交付判断。问题回主做定位最小修正范围，旧观察保留。

这不是四角色逐步串行盖章：故事审核与成片盲审各有一次独立观察，生成前按 Panel 检查；监督只在重要交接或用户要求改变后介入，代理只在实际分歧时启动。审核职责可由不同新实例承担，不让同一个审核者带着故事答案再做最终盲审。

## 短交接与记录

在当前项目产物目录用[交接模板](../assets/story_handoff.template.md)维护一份 `handoff.md`；已有等价交接页就复用。需求、决定、当前版本、下一步与阻塞保持简短，正文引用现有主源，不复制完整故事。用户要求保留原意与来源位置，后续取代注明依据；制作选择另列，不用摘要覆盖原意。阶段完成、用户改要求或采用版本变化时更新，不按每次工具调用写日志。

审查结果按实际被审版本保存到项目 `reviews/`，使用[结果模板](../assets/story_review.template.md)。记录实际交付的输入清单、宿主/观察工具、是否继承历史、输出及局限；文件摘要可用 SHA-256，文本稿用版本及实际材料摘要。独立观察先保存，之后的需求比较另列，不改写原观察。新版本首次观看须新实例；原实例继续仅叫局部复查。

派发前读取最新材料；返回时若源版本已变化，先判断结果适用范围，不能把旧版审核写给新版。任务报告只证明观察/核对结果，Canvas run/review 仍是媒体状态来源；不把新字段塞进现有 review 协议。最终成片报告绑定最终文件，不能用单个源 run 冒充整片采用。

持续制作仍在现有接续中登记真实执行单元。主会话收到结果后核实并处理，只回收成果摘要、具体问题和下一步；详细素材与工具日志留在对应任务。换阶段后新的主做读取交接页和指定主源，不读取全部历史。失败/unknown、暂停与尾帧依赖沿用共享规则。

## 同一宿主内的适配

共同约定只要求独立上下文、指定材料、结果/状态与中断处理，不绑定模型或宿主工具名。派发前核实实际能力；无并行能力可串行独立执行，无干净上下文能力则明确缺口，不在原会话扮演“首次观看”。配置文件存在不证明已加载。

| 宿主 | 使用方式 | 核实点 |
| --- | --- | --- |
| Codex | 用实际子代理接口；本会话提供 `fork_turns="none"` 时用于新阶段/独立审核 | 不继承父历史，但仍可能有宿主规则/共享工作区；只传该角色材料，不为盲审加载主 Skill 全文 |
| Claude Code | 原生独立子代理，角色任务使用本参考相应材料和提示词 | 核对自动加载的项目指令、记忆及可用工具；不用继承整段对话的 fork 充当盲审 |
| Pi | 使用已安装并核实的独立子代理扩展 | Pi 核心不默认提供子代理；官方示例使用独立进程，仍需核对输入与扩展加载。缺失时报告，不自动安装 |

角色说明只在本目录维护；宿主项目配置按需要引用，避免复制三套完整提示词。本轮不预装 Claude/Pi 扩展，不把它们写成已验证。宿主后台唤醒另按接续指南核实，普通角色分工不依赖后台常驻。

## 成片盲审

优先使用能读取实际音视频、且不继承制作历史的观察入口。可用[独立媒体观察脚本](../scripts/blind_review.py)复用现有 [MiMo 分析](../../mimo-video-understanding/SKILL.md)：它只发送中性提示词和指定本地媒体的临时快照，不发送路径、剧本、交接页、对话或历史结论；请求无文件工具。它是外部媒体分析，不是本地推理，沿用用户已给 MiMo 授权；若用户限定离线，停止该入口并使用已核实的本地观察能力。

~~~powershell
# 先只准备请求说明，不访问网络；正式执行使用另一个新报告路径并去掉 --prepare-only。
./.venv/Scripts/python.exe .agents/skills/zero-to-story/scripts/blind_review.py --video "<实际成片.mp4>" --output "<项目目录>/reviews/<版本>-prepare.json" --prepare-only
~~~

脚本不接受自定义问题或背景文件，以免在问题中泄露答案；真实请求使用项目既有 MiMo 默认模型，可显式选择该入口已支持的型号。报告绑定实际输入摘要和采样参数，原始观察与准备/失败状态分开，不覆盖旧报告、不自动重试、不写 ACCEPT。原媒体超过已有接口限制时，按授权另做保留声音的完整压缩副本，记录原片与副本关系；片段或抽帧只能支撑局部观察，不能称为整片盲审。

媒体中的片名、字幕和音轨是作品内容；不要额外附加揭示动机的文件名或作者说明。若媒体自身含有不对观众展示的制作注释，先准备正确的观众版本。模型能否理解声音与连续运动以实际观察能力为准，报告中的自述不证明覆盖；音轨检查有缺口时单独记录，不用无声技术候选替代最终成片。

盲审观察是本次最终验收的输入，按[视频验收](video-qc.md#最终成片)结合实际视听与用户采用判断处理；不能据 AI 复述宣称大众接受，也不进行多模型投票。无实际媒体或本轮仅改规则时，不执行盲审。

## 方法来源与取舍

参考 Eian 的 [X 长文](https://x.com/EianLu/status/2118317430665613741)及[含提示词转载](https://haowenji.com/articles/x-2118298893238845441)：采用分工、独立阅读、输入一致性、需求监督和局部修正思路。[项目提示词](story-collaboration-prompts.md)为面向本项目的改写，不是原文复制或 Seedance 参数说明。

保持安静、对称、留白、连续剧情及多种生成模式的创作空间；不引入固定机位配额、黄金比例硬门、每镜必备首尾帧、逐秒动作配额、预算审批或“代码能修一切”的承诺。H3 提示词字段仍由原写作入口负责，不把七段思考提纲当成新的提交格式。

宿主参考：[Claude 子代理](https://code.claude.com/docs/en/sub-agents)、[Pi 官方扩展示例](https://github.com/earendil-works/pi/tree/main/packages/coding-agent/examples/extensions/subagent)。宿主版本与本地能力以实际检查为准。
