# 视觉化导演：让名词有形、关系可见

## 先选素材，再设计图解

先读 [原始媒体采集与剪辑](source-media.md)。有真实视频时优先让观众看到动作及结果，有图片时让观众看清主体和细节；图解补上素材中看不见的关系。不能把所有素材统一缩成小窗，外面大半屏仍是标题与要点。

例如原帖同时有角色宣传片、产品演示、价格图：可从角色片段切入，借真实演示说明任务，再短暂切同尺度成本图，回到原片的结果段。角色动画属于宣传视觉，不据此推断模型能生成该动画；演示若加速或删去等待段，应标明，不能拿剪辑节奏证明性能。

## 选择画面语法

| 信息形状 | 主视觉与动作 | 事实边界 |
|---|---|---|
| 新产品/新事件 | 真实主体出现，突出变化部位，连接具体使用场景 | 不以生成现场代替实拍 |
| 流程与机制 | 输入对象进入系统，经过有依据的环节，输出结果 | 未知过程用虚线/问号，不补造内部机理 |
| 分层架构 | 等轴模块或剖面逐层展开，焦点从接口走向结果 | 图形是示意，尺寸无依据时不按比例暗示 |
| 数量/增减 | 同基线条形、点阵、时间曲线，标注端值及单位 | 非零轴须显著说明；估计/预测与观测值区分 |
| 成本/效率比较 | 同样任务的两条路径或等尺度容器，对齐条件 | “少三成”不等于“快三成”；面积体积不乱映射数值 |
| 影响与取舍 | 同一主体分为受益/代价路径，显示适用边界 | 场景预测明确使用可能/假设 |
| 地理/历史 | 可追溯底图、时间线与位置迁移 | 地名、边界、距离和时间需有来源 |
| 引用/证据 | 短暂出现真实局部，停靠、指认，再转回解释图 | 保留会改变含义的上下文 |

可识别实体比泛化光球更有效：算力可表现为有标识的处理模块；任务排队可用任务包进入处理通道；信息筛选可用不同属性的卡片经过筛选节点。隐喻必须说得清映射与边界，不能让“水流速度”暗示没有来源的性能数据。

## 镜头设计

每镜写明确的三个状态：
- 起始：主角在哪，屏幕占多少，观众先看什么。
- 变化：哪个对象如何改变，由何事实或语义触发。
- 落点：最终结果是什么，保留多久供人理解，下一镜接什么。

“渐入标题→整图放大→淡出”通常只有包装，没有解释。改成“原队列保留→新路径出现→同任务进入两条路径→结果并排停留”，才表达结构关系。关键数字锁定后可从约2秒阅读窗口开始预览调整；不以固定秒数替代真实可读性判断。

屏幕保留关键词、单位与短结论；出处仅按 [用户询问卡](output-preferences.md) 的选择显示，旁白讲完整逻辑。原则上一个注意力中心，同时变化的附属元素要服务同一动作。静止阅读段合理；不是每一帧都需要运动。不同布局用共同对象、位置或颜色语义连接。

## 分层与小屏

背景层提供环境；主体层承担过程；数据/文字层保持精确；必要示意标识清楚而不抢主体；来源层默认关闭，仅在用户选择开启时显示。裁切或缩放后重新对齐批注，不把页面坐标与屏幕坐标混用。

按真实发布平台的覆盖区预览；未知平台时先留上下及右侧余量，在约360–430px观看宽度检查。不要把仓库的某组像素安全区当通用平台规定。大标题不能挤掉主体、单位和条件。无关动画、闪烁装饰和重音会分散理解，优先删。

## 设计练习示例（虚构，不可作为资讯事实）

假设资料仅说“系统增加了一个缓存层”，没有速度测量：可将重复任务先进入缓存、未命中再去处理器，标明“概念示意”；不能画成三倍速度或编造耗时。证据镜展示原文对应句，解释镜只讲有依据的缓存作用。若具体命中逻辑也未披露，就画成“新增缓存模块”结构示意而不演示未经证实的路径。
