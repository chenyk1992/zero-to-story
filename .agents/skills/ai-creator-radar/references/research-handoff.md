# 热点数据、判断与账号研究交接

本文件只协调已有入口和数据；生产与授权遵守[共享规则](../../../../guides/ai-system-prompt.md)，不增加采集器、统一数据库或新自动化。

## 按本轮交付选入口

| 当前请求 | 入口与停止位置 |
| --- | --- |
| 只取榜单、公开数据或快照 | [hot-collect](../../hot-collect/SKILL.md)，返回实际数据、采样时间与来源状态 |
| 从已有热点库排序、比较或做卡片 | [topic-scout](../../topic-scout/SKILL.md)，读取既有库；缺数据说明缺口 |
| 结合账号找题、对标、脚本或复盘 | [ai-creator-radar](../SKILL.md)主责，先复用已有证据，按缺口选择采集或判断层 |
| 已给明确选题与素材，只要脚本 | 直接写所请求稿件，不为完整流程重新采榜或打分 |

用户点名的 Skill 和数据范围优先。综合需求由主会话组合，不要求用户选工具；无关来源缺失不阻塞已有依据支持的工作。

## 两类数据保持各自口径

| 数据 | 实际形态与消费者 |
| --- | --- |
| hot-collect | `--data-root` 下 `snapshots/YYYY-MM/*.json`，顶层含 `collected_at/sources/contracts/records`；topic-scout 读取该库 |
| radar 浏览器/导出观察 | `--store` 下 `snapshots/*.json`，含 `schema_version/source_id/observed_at/items`；radar.py analyze 读取，细节见[数据契约](data-contract.md) |
| topic-scout 输出 | 含 `scoring_version/snapshots_used/candidates` 等判断结果；供主会话引用，不当作原始观察导入 |

目前没有两类快照的通用转换器。复用是引用真实文件或输出、日期、查询/样本范围和来源状态，在当前研究稿中分别解释；不能只改目录或字段名后互读，不能直接相加不同平台指标。评分为排序线索，不是预测概率，缺失信号不由零分补成已验证事实。

## 根据副作用选择命令

- 只读已有热点库并避免供给搜索时，用 `scout.py score --data-root <热点库> --supply-search 0`；S5 未查，报告该缺口。`cluster` 与 `card` 也读取热点库，卡片骨架不证明实际供给已查。
- 仅采集用 `collect.py --collect`；`daily.py` 是采集＋判断组合，会联网，只在本轮确需两者时用。doctor/probe 可能联网，按各自参数核对，不作为离线测试默认步骤。
- radar 的 `analyze` 只处理其已有观察；公开直读、浏览器或本地小红书框架仍按各自来源与失败策略执行，不因协同改成另一种重试规则。
- 仅用已有资料的请求不补采。用户允许新研究时只补与目标有关的缺口，不重复采集已有且适用的证据。来源受限时保留缺口，不借换入口重试同一失败来源。
- 一次研究不建立定时任务；持续采样按用户明确需求和宿主正式自动化入口设置。

## 返回研究主责

返回本轮实际使用的文件/输出及来源口径、候选理由与可获得性、缺失或陈旧证据，以及可继续的具体工作。已有研究稿直接更新相关部分，不新建第二套选题表。需要对标时区分标题/指标与实际媒体观察，后者按[视频拆解](../../video-deconstruct-analyzer/SKILL.md)处理；账号研究沿用[内容研究](editorial-workflow.md)，不凭历史案例断言当前产品可用性。

用户只要一条就给一条；要脚本则先交可审阅稿与必要来源。媒体生成、安装、发布和定时执行均不因研究交接自动发生。
