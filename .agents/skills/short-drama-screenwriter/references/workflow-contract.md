# 短剧工作流契约

共同授权、停止和数据边界见[项目共享生产规则](../../../../guides/ai-system-prompt.md)。本文件只说明短剧阶段、产物和必要的创作检查；不要把它当作视频执行或 QC 手册。

## 目录与状态

用户要求创建、保存或续写项目时，才在用户指定位置落盘；未指定时使用：

~~~text
.short-drama/{drama_title}/
├── .drama-state.json
├── creative-plan.md
├── characters.md
├── episode-directory.md
├── episodes/ep001.md
├── handoff/project.json
├── handoff/characters_visual.md
├── handoff/ep001/storyboard_brief.md
├── handoff/ep001/cut_notes.md
├── compliance-report.md
└── export/{title}.md
~~~

按当前阶段创建文件，不预建空目录。只要对话成稿或审阅，直接回复内容，不创建状态。续作只读用户点名的剧目。

状态只记录已确定事实，例如：

~~~json
{
  "currentStep": "start|plan|characters|directory|writing|review|export|handoff",
  "genre": ["主类型", "辅类型"],
  "audience": "目标受众",
  "tone": "基调",
  "totalEpisodes": 1,
  "completedEpisodes": [],
  "bridgedEpisodes": [],
  "language": "zh",
  "mode": "domestic",
  "dramaTitle": "剧名",
  "endingType": "大团圆|开放式|悲剧"
}
~~~

保留已有字段和文件；只更新当前命令涉及的内容。

`endingType` 示例表达结局走向，不把反转当作互斥结局。反转机制与观众/角色获知安排按[通用反转](reversal-design.md)写在现有 creative-plan / 剧本 / 交接备注中；历史 `endingType: "反转"` 保留，不自动迁移或推断它是大团圆、开放式还是悲剧。

## 阶段交付

先区分独立情景喜剧与连载微短剧。独立喜剧的方案、角色、目录和分集采用[喜剧写作](sitcom-writing.md)，下列付费/爽感/反派/感情线要求只适用于需要它们的连载路径；不强加三候选、三幕四段、固定场句数或下集预告。只写用户要求范围，按当前时长完成铺垫、升级与回收。桥接模板继承当前类型、画幅、风格、时长和完整对白来源。

### /开始：选题

读取 genre-guide.md；独立喜剧转 sitcom-writing.md。确定当前类型、受众、基调和范围，连载再记市场/集数。只要对话稿不建状态；要求保存/续作时才更新。已要求下一阶段直接继续。

### /创作方案：全剧结构

独立喜剧只读 sitcom-writing.md，交当前范围的引擎、人物目标、升级与回收，不套以下连载清单。连载读取开场、付费、节奏和爽感参考，保存需求时写入 creative-plan.md：

- 3 个剧名候选；
- logline、背景、核心矛盾；
- 三幕结构和四段情绪走向；
- 主线、感情线、爽点/悬念密度和付费点；
- 结局、伏笔和主要回收点。

结构为指导，按用户指定的集数和时长调整。

### /角色开发：角色与对手

独立喜剧按 sitcom-writing.md 写目标、地位、预期与关系；连载需要反派设计时读 villain-design.md。角色记录保留姓名、年龄感/身份、性格、动机、弧光和识别行为，秘密/关系图按需。反派不凑等级，感情线只写有用节点；只要对话稿不落盘。

### /目录：分集目录

独立喜剧不强建多集目录，需要系列时按当前因果列单元；连载才读付费和节奏参考。目录写标题、概要与适用剧情标记，付费/感情只在需要时列，不凑数量。只要对话稿不落盘。

### /分集 N：剧本

支持单集、范围和 next。独立喜剧只按 sitcom-writing.md 完成当前故事；连载按集数读节奏、爽感、钩子，第 1 集加开场，付费集加付费点。保存需求时写 episodes/ep{NNN}.md，只要对话稿不落盘。

国内格式示例：

~~~markdown
# 第 {N} 集 · {标题}
> 位置：{阶段} | 情绪：{1-5} | 关键词：{3 个}

## 场次一 · {地点} · {时间} · {内/外景}
△（{全景/中景/近景/特写/俯拍/主观}）{可拍画面}
**{角色名}**（{动作/语气}）：“{台词}”
♪ {音乐或声音提示，可省略}

## 本集结尾
{连载需要时写钩子；独立单集、完结集写已定收束或情绪落点。实际发生的结尾动作、揭示与对白须交给下游可拍节拍，不因本区标题而省略。}
## 下集预告
{连载中间集需要时填写；与本集已发生的剧情分开}
~~~

海外格式使用 INT./EXT. LOCATION — DAY/NIGHT、英文景别和英文对白。先保持剧情事实，再做目标市场的文化和语域适配。

连载剧的默认预算可参考 3–6 场、15–25 句对白、一个主冲突和一个副冲突；用户指定的时长、场景和对白优先。每场至少让观众看见一个目标、阻碍或变化；不要为了数量添加空场。

### /自检 N：一次创作检查

只在用户要求时检查已完成内容；不打分，不做全量 QC。用三段话或短表回答：

1. 剧情：开头是否立即建立问题，中段是否推进，结尾是否留下钩子或情绪落点；
2. 可拍性：动作、场景、对白、声音提示和格式是否足够清楚；
3. 连续性：与已写内容的角色、时间线、道具和伏笔是否冲突。

只列必须修正的问题和少量可选建议；没有阻断问题时写“创作检查通过”。

### /导出：完整剧本

至少有一集完成后写入 export/{title}.md，包含封面信息、300–500 字梗概、角色表、目录和已完成剧本；未完成集数明确标注。

### /桥接 N：创作侧 handoff

至少一集完成后，读取 handoff-mapping.md 和 handoff-brief-template.md，按需读取 JSON 示例。创建或更新：

- handoff/project.json：剧名、默认画幅、目标总时长、风格和情绪；
- handoff/characters_visual.md：人形外貌/服饰或非人身体结构、识别特征和关键道具；
- handoff/ep{NNN}/storyboard_brief.md：本集梗概、角色、场景、可拍节拍和视觉规范；
- handoff/ep{NNN}/cut_notes.md：钩子的剪辑意图、宣传预告、付费点、对白/环境声/动作声/外部口播意图；本集实际结尾事件同时进入 storyboard_brief 的可拍节拍，不只留在备注。

只读剧本正文，不改剧本；不写 Canvas ID、快照、执行状态、真实媒体或 QC。保留用户指定的场景、角色、时长和画幅；只有用户授权压缩时才合并场景。每个节拍写清主体与空间关系、镜头目的、可见结束状态和精确对白。下游再把节拍拆成合法 Panel。

### /出海：格式与文化适配

读取 genre-guide.md 的出海部分，更新状态中的 mode/language，将剧本切换为目标市场格式。保留剧情功能和人物目标，调整称谓、制度、笑点和语域；不要机械直译。

### /合规：风险检查

读取 compliance-checklist.md。按当前题材和市场检查红线、关系/价值观风险和必要的表现边界，写入 compliance-report.md。只报告实际发现的问题、位置、优先级和改法；没有问题时简短记录通过，不生成逐项空白表。

## 交付前的创作标准

- 故事事实与用户输入一致，精确对白/数字/品牌名不擅自改写。
- 场景和动作能被拍摄者直接理解；每个镜头或节拍有目的、主体、变化和结束状态。
- 角色声音、空间关系、道具和时间线前后一致。
- 音频提示只表达意图；实际音频、字幕和生成结果由下游确认。
