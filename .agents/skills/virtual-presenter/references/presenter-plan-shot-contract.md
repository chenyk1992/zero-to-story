# Presenter Plan 与 Shot Contract

共享授权和实际结果规则见[项目共享生产规则](../../../../docs/ai-system-prompt.md)。本文件只定义数字人口播计划的字段和创作标准。

## 计划用法

presenter_plan.md 是唯一创作信息源。模板中的空字段要补齐，或写“不适用/无”；不要复制一份执行状态到别处。创作阶段可用：

待确认 → 已确认 → 进行中 → 完成

上游已确认字段被修改时，把受影响阶段和下游改为需重审。外部能力或证据不足时标记暂停，并保留原因。

计划至少记录：

| 阶段 | 关键事实 |
|---|---|
| 输入规格 | 角色、声音、语言、环境、画幅、总时长、受众 |
| 环境（需要时） | 全景比例、manifest、方向视图、区域和站位 |
| 文案 | 每段口语、时长、停顿、重音、发音 |
| Shot Plan | 每段的 Shot Contract |
| H3/Canvas | 引用槽位、提示词、provider/mode、参数、快照状态 |
| 结果 | 实际文件、实际末态、需要时的音频证据和判断 |
| 成片（需要时） | 接受的片段、顺序、音频/字幕和最终文件 |

计划记录事实即可；执行判断写在对应 Panel 行，不另建 QC 报告。

## Shot Contract 必填字段

每条 Shot/Panel 是一个可独立交接的 Clip，至少写：

- **身份**：稳定 shot_id、revision、目标画幅、4–15 秒时长。
- **空间**：环境区域、主体站位、朝向；需要 360°时写 yaw、pitch、FOV，不能只写“室内”。
- **镜头**：景别、机位高度/朝向、一个运镜及速度；无运镜写锁定机位。
- **表演**：起始姿态、视线、口播、一个信息意图、主动作、结束姿态；标记 L0/L1/L2（见下表）。
- **声音**：对白或口播、停顿/重音、环境声、起止尾音和声音参考用途。
- **引用**：角色图、全景、方向视图、声音参考；第二条起按模式需要引用上一条完整 ACCEPT 片。
- **连续性**：需继承的身份、服装、光向、道具、站位、朝向和未完成动作；本条可见末态。
- **验收重点**：本条必须能观察的主体、动作、空间或声音要求。

## 导演标准

先写本条的镜头目的，再写观众看到的因果动作：起始状态 → 准备 → 一个主动作/语言强调 → 稳定末态。镜头运动要服务视线或信息变化，声音进入点要与口播重音或动作相符。保持自然呼吸、眨眼、轻微视线和重心变化即可；不要在短段里堆叠手势、走位和运镜。动作不能只写“自然”“真实”，要写身体、道具、方向和停点。

## 动作预算

| 预算 | 可做 | 避免 |
|---|---|---|
| L0 | 呼吸、眨眼、自然口型、一个微表情；机位基本锁定 | 新手势、转身、道具交互、明显运镜 |
| L1 | L0 加一次视线/头部转移或一个小手势；一次轻微推拉/横移 | 第二个手势或信息转折、快速走位 |
| L2 | 一次拿取、指向、转身等主动作，加一项镜头变化 | 第二件道具、复杂走位、多个信息点 |

口播、动作和镜头无法在 4–15 秒自然完成时，先删次要信息、延长、或拆成下一条；不靠快嘴和跳切掩盖超载。

## 环境方向

只有当空间方向会影响 Shot 才建立 Environment Pack。源图需为 2:1 equirectangular；使用脚本生成并登记 yaw 0/90/180/-90、pitch 0°、FOV 90° 的实际视图。计划要写清每个区域“主体在哪里、镜头朝哪里”。缺少可核实的空间输入时保持待确认。

## 修改与接续

文案、时长、画幅、角色锚点、环境方向、声音、引用或连续性末态改变时，更新当前 Panel 草稿并提升 revision；已冻结快照和已接受输出保留。不同画幅另建序列。只有上一条完整 ACCEPT 片能成为普通连续性参考；精确首帧必须来自已接受实际输出的真实尾帧。拒绝、INCONCLUSIVE 或执行错误时暂停依赖它的下一条。
