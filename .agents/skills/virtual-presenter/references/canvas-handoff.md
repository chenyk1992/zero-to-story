# Canvas Handoff

共同的角色、Panel ready、实际末态/音频验收和授权规则见[项目共享生产规则](../../../../docs/ai-system-prompt.md)。本文件只描述数字人口播从已确认 Presenter Plan 到 Canvas 视频节点的交接。

## 边界

`virtual-presenter` 决定角色、环境、文案、Shot Contract、引用语义和内容验收要求；`h3-prompt-writing` 生成当前 Panel 的最终 H3 文本；`canvas-workspace` 把这些固定事实保存到目标视频节点。保存只是草稿，不生成媒体。页面确认或对话明确授权后，Canvas 服务冻结 `execution_snapshot` 并按已选能力提交一次。

用户选择 `comfy` 时，脚本型能力由 Canvas 服务调用 [comfy-video-executor](../../comfy-video-executor/SKILL.md)。创作 Skill 不直接运行 comfy-cli，不修改 Canvas 数据库，也不在旁路保存另一份执行状态。选择其他提供方时，必须是当前 Canvas 已接入且用户明确选择的能力；缺失就报告，不静默切换。

## 单 Panel 节点

每个 Shot/Panel 使用一个独立 video 节点。保存或确认前，从最新 `presenter_plan.md` 复制以下已确定事实：

- 稳定的 `panel_id`、目标画幅和 4–15 秒时长；
- 由 `h3-prompt-writing` 返回的完整提示词，逐字保存，不再优化；
- 明确的 `provider`、`model`、`mode` 与该能力要求的参数；
- 当前 Panel 所需的最小素材，以及每项素材的语义用途；
- 外部声音、字幕和其他确定性后期责任；
- 实际内容验收要求和连续性末态。

修改节点只更新下一次生成草稿。已经确认的请求继续使用原快照；已经生成的媒体不会因草稿变化而改变。需要新版本时，先完成修改，再由页面确认或对话明确授权新的固定快照。

## 引用语义

引用编号不能因为缺项而移动：

| 逻辑槽位 | 语义 | H3 标签 | Canvas 绑定 |
|---|---|---|---|
| `ref_image_0` | 角色图/身份锚点 | `<Picture 1>` | 第一项角色参考图 |
| `ref_image_1` | 360°全景或环境源 | `<Picture 2>` | 第二项环境参考图 |
| `ref_image_2` | 当前 yaw、pitch 0°、FOV 90°方向视图 | `<Picture 3>` | 第三项方向参考图 |
| `ref_audio_0` | 声音参考 | `<Audio 1>` | 声音参考输入 |
| `ref_video_0` | 同画幅上一条已接受片 | `<Video 1>` | 普通视频参考输入 |

首片没有上一条接受片时省略 `ref_video_0`，绝不拿 contact sheet 或其他图片填补。后续 Panel 只使用同画幅上一条完整 `ACCEPT` 视频；它是普通连续性参考，不等于精确 `first_frame`。如果当前模式确实要求精确首帧，只能从已接受的实际输出提取真实尾帧、导入画布并绑定到 `first_frame`。失败、`REJECT` 或 `INCONCLUSIVE` 的输出不能进入下游节点。

存在普通视频参考时，是否同时附加独立声音参考由当前 Shot Contract 决定。不要从素材数量推断模式，也不要为了填满槽位添加无用途素材。

## 确认、执行与回填

1. 核对 Presenter Plan、H3 标签、Canvas 端口和实际素材一一对应。
2. 把提示词、模式、参数、素材、音频/后期责任与验收要求保存到当前节点。
3. 只有页面确认或对话明确授权后才执行；确认会冻结本次 `execution_snapshot`。
4. 脚本型能力由 Canvas 服务执行；Agent 型能力按 `canvas-workspace` 的领取规则处理。每个快照只提交一次。
5. 请求状态未知时核对同一请求，不重新提交或换提供方。实际文件返回后回填原节点。
6. 对故事生产输出查看实际画面和声音，记录实际末态、实际音频证据和一次 `ACCEPT`、`REJECT` 或 `INCONCLUSIVE`。

素材不可用、能力缺失、模式与引用冲突、执行失败或证据不足时，停止受影响 Panel。需要重做时修改当前节点草稿并明确确认新快照；不自动重试、修改提示词或维护恢复循环。

## 接力与最终成片

视频提交保持串行；只有存在连续性依赖时才等待前一 Panel 的实际 `ACCEPT`。下一条 Presenter Panel 可以把上一条完整接受视频作为普通连续性参考；只有模式要求精确首帧时才提取真实尾帧。没有下游用途时不做多余提取。

全部 Panel `ACCEPT` 后，如用户要求完整成片，只对这些已接受的 Canvas 输出做确定性媒体处理：按计划排列和连接片段，替换或保留音频，按明确要求加入字幕并输出目标规格。后期处理不调用生成模型，也不创建另一条视频生产入口。最终必须检查实际文件的可播放性、片段顺序、接缝、声音、字幕和同步。
