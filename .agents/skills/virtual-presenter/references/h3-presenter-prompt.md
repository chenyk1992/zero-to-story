# H3 Presenter Prompt

## 目标

提示词要让 H3 复现一个可信的连续口播镜头：身份、空间、口型、声音、表演和镜头各自可核对，且一条片只完成一个信息意图。提示词不写模型名、文件系统路径、数据库、工作流或最终导出分辨率；这些由 LFO package 和配置层处理。

## 推荐顺序

按以下顺序组织最终提示词，保留具体而可观察的词：

1. **场景与空间**：说明环境 Pack 的区域、yaw/pitch/FOV、机位和主体站位；只使用已确认的方向视图。
2. **角色锚点**：逐字引用已确认角色图的可见身份、发型、服装、配饰和道具；不要添加角色图没有的身份变化。
3. **镜头**：画幅、景别、机位高度、朝向、唯一运镜、速度和稳定性；只使用固定、轻微跟随、Pan、Push-in、Pull-back 或轻微手持。
4. **表演**：呼吸、眨眼、轻微眼神和重心变化作为自然底层；起始姿态 → 1–2 次语言强调动作 → 结束姿态，写明 L0/L1/L2 预算，不写连续动作清单。只有计划中唯一被选中的 Shot 可以包含一次小范围语义走位。
5. **口播**：自然、短句化的文案，停顿和重音；口型与声音同步，语速适合 4–15 秒。
6. **连续性**：若存在 `ref_video_0`，只继承上一条已接受片的可见末态和音频尾音，不重新解释故事；写出本条要保持和要改变的内容。
7. **收束**：镜头和人物停在可供下一条接续的明确末态。
8. **负向**：只列会破坏验收的可观察排除项，例如多人、身份漂移、额外手指、卡口、跳切、方向翻转、文字水印、嘴型与声音失配；不要把 `negative_prompt` 当作 LFO 的独立控制字段。

## 固定引用编号

提示词中的编号与 package 槽位一一对应：

| H3 提示词标签 | package 槽位 | 用途 |
|---|---|---|
| `<Picture 1>` | `ref_image_0` | 角色/身份锚点 |
| `<Picture 2>` | `ref_image_1` | 全景/360°环境源 |
| `<Picture 3>` | `ref_image_2` | 当前 yaw、pitch 0°、FOV 90°方向视图 |
| `<Audio 1>` | `ref_audio_0` | 声音、音色、语速和发音参考 |
| `<Video 1>` | `ref_video_0` | 同画幅上一条已接受片；首片省略 |

槽位下标从 0 开始，H3 标签编号从 1 开始。缺少某一项时保留其语义位置，不把其他引用顺延。contact sheet 只用于用户审阅，不替代 `<Picture 3>`。

## 段落模板

把下面结构展开成最终自然语言，不把标签原样塞给模型：

```text
在已确认的 [环境区域]，主体站在 [站位]，朝向 [方向]。
保持 [角色锚点]。使用 [画幅/景别/机位]，镜头 [唯一运镜/锁定]。
从 [起始姿态] 开始，以 [L0/L1/L2] 完成 [一个主意图]，
自然说：“[口语化文案]”，在 [停顿/重音] 处停顿。
保持 [光向、道具、视线、口型]，最终停在 [可见末态]。
若有 <Video 1>，只延续 <Video 1> 的 [末态差]，不引入新动作。
排除 [与本条验收相关的可观察问题]。
```

把实际路径和内部 ID 留在包的引用映射中，不放进提示词正文。不要使用抽象指令如“表现得更真实”来代替动作、视线、速度和末态。

## Panel 之间的接力

Presenter Plan 确认后，按 Shot/Panel 顺序逐条执行；每个 Panel 使用一个只含当前 Clip 的 execution package。首个 Panel 省略 `ref_video_0`；之后只引用同画幅上一条 `ACCEPT` 片的真实输出，不引用失败或被拒绝的片。

当前 Panel 完成后由调用方做一次最小 `ACCEPT`、`REJECT` 或证据不足时的 `INCONCLUSIVE` 判断；校验或执行失败记为 `ERROR`。下一条 Presenter Panel 使用当前完整 `ACCEPT` 视频作为普通 `ref_video_0` 连续性参考。只有其他下游 operation 明确需要精确首帧时，才从实际输出提取真实末帧并绑定。`REJECT`、`INCONCLUSIVE` 或 `ERROR` 立即暂停受影响接力，不自动重试、不生成候选列表；需要重做时重新构建当前 Panel package 并核对授权。

## 可执行性检查

提交前逐条检查：

- 时长在 4–15 秒；文案在正常语速下能说完；
- 只有一个信息意图，动作符合 L0/L1/L2；
- `<Picture 1/2/3>` 与 `ref_image_0/1/2` 对齐；
- 声音使用 `<Audio 1>` / `ref_audio_0`，后续视频使用 `<Video 1>` / `ref_video_0`；
- 方向视图的 yaw、站位和镜头朝向与环境 Pack 一致；
- 负向内容是可观察的验收条件，而不是未经适配器支持的额外字段；
- 当前 Panel package 已单独 `validate`，并在执行前核对批准的完整文件字节 SHA-256；不覆盖已接受的实际输出。
