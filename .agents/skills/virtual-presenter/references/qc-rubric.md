# Presenter 最小 QC

## 判定原则

QC 只依据当前 Shot/Panel Contract 和实际输出的可观察证据。QC 决策只有 `ACCEPT` 或 `REJECT`，不使用 PASS、REVIEW、FAIL、分数或分级报告；校验或执行失败记为 `ERROR` 并立即停止。已有输出但不可播放时记为 `REJECT`。

每个 Panel 作为独立的短生命周期单元同步执行；调用方在结果返回后做一次最小检查。前一个 Panel 未 `ACCEPT` 时，不启动下一个依赖它的 Panel，也不进行最终组装。

## 检查项

| 检查 | `ACCEPT` 条件 | `REJECT` 例子 |
|---|---|---|
| 文件可用 | 输出文件存在、非空、可解码并能正常播放 | 文件缺失、空文件、无法解码 |
| 明显生成错误 | 没有黑屏、严重损坏、明显画面崩坏或无法辨认的主体 | 黑屏、严重闪烁、融脸、多余主体、明显伪影 |
| 计划意图 | 主体、区域、主要动作和口播大意符合当前 Shot Contract | 身份明显漂移、动作完全错误、关键口播不可懂 |
| 连续性 | 有上一条 `ACCEPT` 片时，当前开头能自然接上可见末态 | 倒带、重复收尾、状态重置、方向明显跳变 |
| 声音（需要时） | 口播/配对音轨存在且核心内容可听清 | 无声、严重截断、噪声盖住核心口播 |

轻微、不影响理解的差异不升级为额外等级。调用方在 `presenter_plan.md` 的当前 Panel 行写一句结果和必要证据即可，不建立单独 QC 报告。

## 执行与接力

1. 当前 Panel 的 package 先 `validate`，并核对用户批准的完整文件字节 SHA-256。
2. 当前执行单元同步等待官方 `comfy-cli` 返回；调用方只做本页最小检查。
3. 下一条 Presenter Panel 将当前完整 `ACCEPT` 视频作为普通 `ref_video_0` 连续性参考；只有其他下游 operation 明确需要精确首帧时，才从实际输出提取真实末帧并写入其 `first_frame`。
4. `REJECT` 或执行错误立即停止，不自动重试、不修改 prompt、不保留失败候选；需要重做时重新构建当前 Panel package 并重新批准 hash。

## 最终组装检查

全部 Panel `ACCEPT` 后，使用已接受片段构建纯 `video.passthrough` assembly package。该 package 独立 `validate`、重新核对完整文件字节 SHA-256，并只执行一次。最终只检查文件可播放、片段顺序正确，以及已确认的音频/字幕策略存在。
