# MG 口播动画

遵守[项目共享生产规则](../../../guides/ai-system-prompt.md)。本 Skill 负责 MG 的创意方案、口播/视觉映射和单 Panel 交接；不直接操作 Canvas 数据库、ComfyUI 或视频提供方。

## 适用范围与交付

用户要把产品、界面、功能说明、发布展示或抽象主题做成 MG 动画时使用。可交付：

- 口播改写与视觉概念；
- 风格/版式、动效时间线和画面文字；
- 交给 h3-prompt-writing 的单 Panel 创作事实；
- 方案确定后交给 canvas-workspace 的提示词、素材、模式、参数、音频/后期责任和验收重点。

用户只要方案或审阅时停在文档；已确定并明确授权时才进入 Canvas。默认一个连续 Clip；只有用户要多条成片或单条时长/能力要求拆分时才建立多个 Panel。

## 输入判断

先复用当前指令和已有计划，整理：主题/产品、口播文案或音频、参考图/截图/Logo/数据、目标受众、时长/画幅、字幕要求和真实/虚构属性。只有缺失信息会改变真实对象保真、交付目标或 Panel 输入时才提问。

| 输入 | 处理 |
|---|---|
| 参考图 + 口播 | 保留对象外观，按口播建立视觉时间线 |
| 参考图、无口播 | 按交付目标做无口播方案；需要代写口播时才问 |
| 无参考图 + 口播 | 用 UI、卡片、图形隐喻或抽象对象解释口播 |
| 无参考图、无口播 | 按主题和规格选方案；真实品牌/对象仍需可靠来源 |

有文案和音频时，以音频节奏为准、文案核对语义；只有音频先转写；只有文案按正常语速估算。精确数字、品牌名、Logo、屏幕文字和引用必须来自用户或可信素材，不让生成模型猜。

## 创作流程

1. **锁定信息**：提炼每段的一个核心信息和观众应理解的结论；区分真实对象、概念对象和抽象主题。
2. **建立视觉系统**：选一个主风格、必要时 0–2 个辅助模块和一条核心结构。统一背景、色彩、排版网格、字体层级、图标/容器和动效语言；不为套菜单添加无关风格。
3. **写时间线**：每段写画面主体、短屏幕文字、对应 Voiceover、元素如何出现/变化/离场、镜头和桥接。让图形动作解释语义，单屏一个焦点，数字与文字留出阅读时间。
4. **定稿与交接**：读取 [H3 MG 提示词模板](references/h3-mg-prompt-template.md)，按需读取风格、元素、文字、抽象或数据参考；把当前 Panel 的创作事实交给 [h3-prompt-writing](../h3-prompt-writing/SKILL.md)，再交 [canvas-workspace](../canvas-workspace/SKILL.md) 保存。
5. **授权后执行**：Canvas 保存的是草稿；页面确认或对话明确授权后冻结快照并提交一次。comfy 由 Canvas 服务调用 [comfy-video-executor](../comfy-video-executor/SKILL.md)。返回实际结果后由调用方按共享规则做一次任务相关验收。

## MG 导演标准

每个段落都要回答：观众此刻要理解什么；哪个视觉元素承载结论；它怎样进入、变化、停稳并成为下一段的桥接锚点。元素运动要有因果（例如卡片聚合成流程、进度线变成结果），镜头只跟随主要信息变化。避免 PPT 式静态轮播、随机漂浮和无意义转场。真实数字、文字和对象必须清楚；复杂信息拆成多个语义段，不靠小字堆满画面。主元素、辅助元素和背景要分层，音效/音乐支持口播而不遮盖。

## 真实对象与品牌

- 真实品牌、真实对象或用户参考图：保留外观、颜色、材质、比例、结构、Logo、界面和关键文字；不虚构型号、卖点或官方视觉。
- 虚构/概念对象：可原创外观、UI 和品牌落版，但不能冒充真实品牌。
- 只有品类没有品牌或图：使用抽象轮廓、通用 UI、信息卡片和图形隐喻，不生成真实 Logo、型号或包装文字。
- 有稳定主体时，开场和结尾回到主体或主题收束；产品、UI、卡片、线条和数据之间要有叙事因果。

## 交给 h3-prompt-writing 的事实

单 Panel 事实至少包括：

1. 生成规格：Panel 时长（H3 为 4–15 秒）、画幅、横竖屏、单/多 Panel、是否口播和音频来源；
2. 产品/主题：真实或虚构属性、外观、功能、必须保真的元素；
3. 视觉系统：背景、构图、层级、材质、UI/图形载体、视觉密度；
4. 核心结构：信息流、流程、对比、中心对象、时间线或聚合等；
5. 时间线：画面、短文字、Voiceover、元素动作、镜头和具体桥接；
6. 文字与音频：只写短标题/关键词/标签/数据，是否需要外部口播、原生音频或确定性字幕；
7. 连续性和必要负向：主体、配色、字体层级、几何语言、视觉锚点以及本条最可能的可观察错误。

H3 正文由 h3-prompt-writing 生成并逐字保存；本 Skill 不在旁路手写第二份模型规则。

## Canvas 关键映射

- 参考模式由已确认用途决定，不由参考数量猜：无参考可用 T2V；明确精确首帧用 I2V；明确精确首尾帧用 FL2V；普通身份/构图/风格图或视频参考用 R2V。
- 每项参考写清实际来源、用途和保真要求；产品图由 Skill 生成时也必须先作为素材审阅。
- 只有旧输入明确把 pixel_ratio 当作同一 MP 像素预算时，才将该值写入 Canvas parameters.megapixels；不要把画幅或像素宽高比当作 MP，未指定不猜。交付分辨率属于确定性后期，不塞进提示词。
- 外部口播音频登记实际素材和后期责任；没有外部音频时写明是否允许能力生成原生音频。普通字幕默认关闭，画面文字不等于字幕。
- 模式、provider 和参数缺失或与参考用途冲突时停在交接前，报告具体缺口；不静默换能力。

## 交付与修改

用户修改时只更新受影响的创作事实和草稿；已冻结请求保留原输入，未受影响内容不重复确认。交付方案时给出视觉结构、时间线、素材缺口和音频/字幕路径；交付交接时给出完整 Panel 输入和授权依据；执行结果由调用方记录实际文件、任务相关末态/音频证据、一次判断和未解决问题。
