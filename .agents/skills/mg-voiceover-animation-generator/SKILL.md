# MG 口播动画生成器 Skill

当用户要制作产品、界面、功能说明、发布展示或抽象主题的 MG 口播动画时使用。本 Skill 先遵守[项目共享生产规则](../../../docs/ai-system-prompt.md)，负责文案、产品/视觉素材、风格与语义映射、H3 提示词和创作决定；执行子代理使用用户在当前宿主配置的子代理模型与推理档位完成一个冻结 Panel 工作单元，不复制主会话设置或写死型号。执行单元查看实际输出，记录实际末态和实际音频证据，作出 `ACCEPT`、`REJECT` 或证据不足时的 `INCONCLUSIVE`，再按实际依赖准备后续 Panel。

创作方案确定后按已选择的入口交接：画布使用 [canvas-workspace](../canvas-workspace/SKILL.md) 的固定快照、单次提交和实际媒体回填，不要求执行包、包 hash 或 assembly 包。只有明确选择 LFO package CLI 时，才调用 `lfo.skill_adapter.mg_voiceover.build_package` 并走 `validate → execute --approved-sha256`。两条入口都由执行适配层调用提供方；本 Skill 不直接操作 ComfyUI、数据库或视频提供方编排。

风格不预设为固定菜单。根据输入、参考素材和口播语义选择一个主风格、0-2 个辅助视觉模块及核心结构；只有多个方向都成立且结果差异显著时才询问选择。真实对象必须保真，虚构概念可以原创但不得冒充真实品牌。

## 全局命名规则

- 本 Skill 内由 H3 生成的动态影像统一称为「MG 动画」。
- 最终交付称为「最终 MG 动画」或「MG 口播动画生成器成品」。
- 写给 H3 的完整文本称为「H3 提示词文档」或「MG 动画提示词」。
- 仅在指代底层工具、文件格式、用户上传素材或非本 Skill 产物时，才保留「视频」一词。

## 执行流程

1. 判断输入：产品图/包装图、App/SaaS 截图、口播文案、口播音频、产品资料、真实对象、虚构概念或纯主题。
2. 补齐决策：优先复用当前指令和已有计划；信息足够时直接采用合理默认值。只有缺少真实对象保真所需的参考图、虚构/真实属性会改变结果，或无口播会改变交付物时才提出最少的定向问题。
3. 分析文案与素材，选择主风格、辅助模块、核心结构、画面关键词和保真约束；产品图若由 Skill 生成，先作为素材文件审阅。
4. 按需读取参考资料，写成可审阅的 Markdown 文档；环境有文档或画布展示能力时可同步展示，但不能依赖某个旧 Hub 工具。文档结构见 [H3 提示词模板](references/h3-mg-prompt-template.md)。
5. 如果用户要求审阅或方案仍有未决创作选择，先交付可审阅文档；如果当前指令或已有计划已确定方案且信息足够，直接准备所选入口的执行输入。真实素材、授权和当前入口的输入检查仍须齐全。
6. 用户修改时更新文档和受影响的创作素材；不重复询问已经确定的事项。明确当前 Panel 的 operation、提示词、素材用途、参数、音频/后期责任和验收要求。画布任务把这些输入交给 `canvas-workspace`，领取固定快照并回填实际结果；外部口播和准确文字按计划在后期落实。请求状态未知时核对原请求，不重新提交。完成画布交接后不执行下面的 package CLI 步骤。

### 仅在明确选择 package CLI 时

调用 `lfo.skill_adapter.mg_voiceover.build_package`，把当前 Panel 的 H3 提示词、素材、授权和输出策略写入一个 `lfo.video-execution.v1` 单 Clip 包。每个 Panel 包和最终 assembly 包都直接写在 `workspace/projects/<project_id>/` 项目根目录，使用唯一文件名，不为包建子目录；素材放项目内用途明确的目录。

将当前包和素材交给 LFO。先运行 `validate`，使用其返回的 `package_sha256`。核对该完整文件 hash 的已有批准或适用持续授权；只有未覆盖时，才请求一次精确 hash 批准：

```text
python -m lfo.cli.main validate panel-P001.execution-package.json
python -m lfo.cli.main execute panel-P001.execution-package.json --approved-sha256 <PACKAGE_SHA256>
```

`PACKAGE_SHA256` 必须逐字使用 `validate` 返回的完整 package 文件字节 SHA-256；任何包内容变化都要重新 `validate` 并核对授权。`execute` 同步调用官方 `comfy-cli`；返回后执行单元查看实际文件，记录实际末态和音频证据，作出 `ACCEPT`、`REJECT` 或 `INCONCLUSIVE`。只有下一 Panel 确需精确首帧且当前 Clip 已 `ACCEPT` 时才提取真实末帧；普通 R2V 可按计划引用完整接受视频，T2V/硬切无需尾帧。全部 Panel 接受后，用 `build_assembly_package` 构造全 `video.passthrough` 包，独立校验、核对授权并执行一次，落实最终口播和输出策略；单 Clip 也如此。执行失败、拒绝或证据不足时暂停受影响任务，不自动重提。

## 输入规则

1. **有参考图 + 有口播**：分析参考图与口播，生成保真、口播驱动的 H3 提示词文档；用户要求审阅或方案仍有分歧时再停留在文档阶段。
2. **有参考图 + 无口播**：如果交付目标和画面文字足够明确，直接采用合理的无口播方案；只有需要代写口播、缺少关键信息或真实对象无法保真时才询问。
3. **无参考图 + 有口播**：按口播生成信息讲解型、功能说明型、界面演示型或抽象主题型 H3 提示词文档，并沿当前授权流程继续。
4. **无参考图 + 无口播**：按已给主题和输出规格直接建立方案；仅在主题、时长、比例或真实/虚构属性的缺失会改变成品时提问。

处理规则：

- 同时有文案和音频：以音频为节奏基准，以文案为语义参考。
- 只有音频：先转写音频，再分析语义。
- 只有文案：按文案估算时长并规划秒数分镜。
- 有参考图：外观、颜色、材质、比例、Logo、结构和关键识别元素必须保真。
- 没有产品图：使用抽象主题符号、信息卡片、UI/图形容器和视觉隐喻；如果用户允许概念产品，可以原创产品外观。

## 品牌与产品真实性规则

- **真实品牌 / 真实对象 / 用户上传参考图**：必须保持外观、颜色、材质、比例、Logo、结构、系统界面和关键识别元素；不得虚构 Logo、型号、包装文字、系统界面或官方视觉资产。
- **虚构品牌 / 概念对象 / 用户自定义名称**：如果用户明确提供虚构名称、概念设定或原创对象设定，可以围绕该名称生成原创外观、界面和品牌落版；但不得出现真实品牌 Logo、真实系统界面或真实商标。
- **只有品类，没有品牌或参考图**：默认使用抽象轮廓、通用 UI、信息卡片和图形隐喻；不要生成真实品牌 Logo、具体型号或包装文字。
- **中心对象连续性**：有参考图或概念对象时，主体必须作为全片视觉锚点，开场和结尾都应回到主体或主题卡。

## 执行包不变量（仅 package CLI）

- **参考路由**：`generation_operation` 必须由当前指令或已确定的创作方案显式给出，适配器不按参考数量猜测。无参考可选 T2V；只有被明确确认是精确首帧的单张图片才可选 I2V 并绑定 `placement="first"`；精确首尾帧选 FL2V；普通身份、构图、风格图片或视频参考选 R2V，并使用类型匹配的 fixed slot。素材都以文件和引用元数据进入执行包。
- **连续性**：默认生成一个连续 Clip，不拆多段、不生成静态分镜再合成；只有用户明确要求多条成片时才创建多个独立执行包。
- **像素比**：用户说的 `pixel_ratio` 映射为 `GenerationRequirements.megapixels`；未指定时保持空值，不猜测默认像素预算。H3 生成画布只写 `aspect_ratio` + 可选 `megapixels`（例如 `9:16` / `0.4`、`16:9` / `0.6`），不要写 generation width/height。`OutputPolicy` 仍可保持 `1080x1920` 等交付尺寸。
- **口播音频**：有外部口播音频时，在生成包中登记音频素材/音轨，并在 ACCEPT 后由 passthrough assembly 实际替换音频；没有外部音频时允许 H3 原生音频并由 assembly 保留。两条路径都要在 H3 提示词和执行包中写明。
- **字幕**：普通字幕默认 `subtitles_mode="none"`。MG 画面中的关键词、按钮、标题和动态字形是设计元素，不等于字幕；只有用户明确要字幕时才改变输出策略并提供字幕内容。
- **素材治理**：每个产品图、参考图和外部音频都要有 `review`、`provenance`，并通过参考位或音轨绑定到 Clip；Skill 生成的产品图也按普通素材文件处理，不绕过执行包边界。
- **授权**：执行包记录当前指令或已有计划对创作方案的授权来源；如果方案没有被确定，先补齐该事实。进入 LFO execute 前仍必须核对当前完整文件字节 SHA-256 的明确批准或适用的持续授权；不能用笼统生成请求代替尚不存在包的 hash 授权。


## 风格组合规则

- 本 Skill 不把风格当成互斥选项。执行时应判断：一个主风格方向、0-2 个辅助视觉模块、一条核心叙事结构。
- 主风格决定整体画面气质、背景、产品呈现和节奏；辅助模块只贡献局部段落或视觉方法，不应把全片风格拉散。
- 风格描写尽量由用户输入和语义自动导出，重点写气质、空间、层级、材质、载体方法和叙事节拍；不预设默认风格，不主动硬写具体色彩。
- 常见组合：
  - AI 平板：高端产品发布片为主，叠加 UI / SaaS 功能演示和数据效率可视化。
  - 智能空调：生活方式家电说明为主，叠加清爽 MG 产品讲解和温控 UI 演示。
  - AI 日程 App：UI / SaaS 功能演示为主，叠加清爽 MG 和数据进度可视化。
  - 虚构智能硬件：虚构概念产品发布为主，叠加高端科技产品发布片和 UI 演示。
- 不要为了套菜单打断用户。用户已经明确“深黑高端科技风 / 清爽生活感 / UI 界面演示 / 家电舒适场景”等方向时，直接按对应组合写提示词。以用户输入为准，不预设默认风格。
- 只有当多个方向都会成立且视觉结果差异很大时才询问。

## H3 提示词输出结构

最终写给 H3 的提示词必须优先采用以下结构：

1. **生成规格**：时长、比例、横竖屏、动画类型、是否口播、是否生成音频；用户提到帧率可保留，但不依赖帧率控制效果。
2. **产品设定**：产品类型、产品名称 / 品牌、真实或虚构属性、产品外观、核心功能、必须保真的视觉元素或不可虚构项。
3. **整体视觉风格**：背景气质、构图、主体光影、UI 风格、质感、视觉密度和整体观感；由用户输入、参考图和口播语义共同决定，不预设默认风格，不强行写死色彩。
4. **核心结构**：优先由知识库决定，可用信息流、对比、流程、中心对象、时间线、看板或聚合收束等结构，不要求每次都用同一条箭头链。
5. **按秒数规划时间线**：每段包含画面内容、文字显示、Voiceover、元素动效和转场方式；必要时补充景别、机位、镜头运动、主体行为、背景运动和声音。
6. **全片转场规则**：不硬切、不做 PPT 式切换；每段之间用对象轮廓、屏幕边框、UI 卡片、圆点、线条、环形进度、关键词字形、设备连接线、进度条或完成勾桥接。
7. **文字规则**：屏幕文字是 MG / UI / 发布片设计元素，不是普通字幕；不生成底部字幕条，不逐字显示整段口播。
8. **对象 / 品牌规则**：真实对象保真；虚构对象可原创但不冒充真实品牌；无品牌无图时只做抽象对象和通用 UI。
9. **音频提示**：整体音乐风格、轻音效和禁止项。

## 高端产品发布片结构

当用户需求偏“高端产品片、科技产品发布、电子产品界面演示、App/SaaS 功能演示、AI 产品发布、产品 Hero”时，优先采用：

```text
主体开场 → 信息痛点 / 使用场景 → AI 或核心系统整理 → 功能界面演示 → 多场景 / 多设备联动 → 数据结果或完成状态 → 主体展示 → 品牌落版
```

写法要求：

- 开场建立产品质感：暗处浮现、边缘轮廓光、屏幕亮起、轻微悬浮或慢速旋转。
- UI 动效从产品屏幕或产品周围自然生长，不要像无关素材独立漂浮。
- 每个功能段都是一个工作流步骤，而不是孤立卖点堆叠。
- 结尾回到产品正面、产品 Hero 或品牌落版。
- 如果有数据或完成状态，进度条、数字、完成勾、状态点必须与前一段 UI 元素连续变形。

## 清爽 MG 产品讲解结构

当用户需求偏“家电、生活产品、服务讲解、功能说明、数据解释、教育/课程/工具说明”时，优先采用：

```text
产品/主题建立 → 痛点或需求 → 核心卖点拆解 → 场景体验 / 流程演示 → 数据或结果证明 → 品牌/主题收束
```

写法要求：

- 产品可以符号化或抽象化，但核心品类必须稳定。
- 信息卡片、圆点、线条、图标、环形进度、UI 面板和关键词是主要视觉语言。
- 单屏只承载一个核心信息，避免密集小字。
- 相邻分镜必须有桥接计划，避免画面像 PPT。

## 高端科技产品发布片风格

适用于 AI 平板、手机、耳机、智能硬件、SaaS、App、AI 工具、车机、可穿戴设备。

视觉方向：由用户输入、参考图和口播语义共同决定；按知识库自动选择背景、构图、材质、UI、图形和节奏，不预设默认视觉模板。

## 产品 Hero + UI 演示规则

- 有产品图时，产品本体必须作为全片视觉锚点，保持外观、颜色、材质、比例、Logo 和关键部件。
- 无产品图但用户允许虚构概念产品时，可以生成原创产品外观、原创 UI 和原创品牌落版。
- 产品可在开场从暗处浮现、边缘光勾勒、缓慢旋转、屏幕亮起、界面展开。
- UI 动效应从产品屏幕、产品边缘、设备连接线或产品周围空间自然生长。
- 结尾必须回到产品正面、产品 Hero 定版、品牌名或主题收束语。
- 产品与 UI、卡片、线条、数据和文字必须有因果关系。

## 相邻镜头桥接规则

- 高端产品片和 MG 讲解片都必须为相邻段落设计桥接。
- 桥接写法必须明确：上一段的什么元素，如何变成下一段的什么元素，转场持续多久，镜头如何运动。
- 推荐桥接：杂乱卡片被 AI 光环吸附并归类；功能卡向右拉伸成时间线；时间线节点飞出成为设备连接点；设备连接线回流到屏幕重组成仪表盘；进度条收缩成完成勾；完成勾变成品牌落版中的光点。
- 不要只写“自然转场、丝滑切换、快速切换、淡入淡出”。

## 提示词审阅规则

- 将完整 H3 提示词写成可审阅的 Markdown 文档，建议命名为「产品名/主题 + MG 口播动画生成器提示词」。
- 文档必须包含制作摘要、真实/虚构属性、输入素材、时长、比例、像素比、风格、核心结构、口播/音频路径、字幕策略和可直接用于 H3 的完整提示词。
- 方案未确定或用户要求先审阅时只更新文档和创作素材；方案已确定时，按所选入口准备画布输入或执行包。
- 用户修改时更新文档及受影响的执行输入；已提交任务仍使用原固定输入。确定后的文档连同素材、授权和验收要求交给所选入口，不重复确认未受影响的事项。

## 默认音频提示

默认写入 H3 提示词：克制、现代、低频干净的高级电子音乐。加入极轻卡片滑动声、AI 提示音、设备连接声、进度完成声和品牌收束音。不要歌词，不要嘈杂人声，不要强烈鼓点盖过口播，不要夸张卡通音效。若用户选择无口播，则音乐和轻音效可以更完整地承担节奏，但仍保持克制干净。

## H3 生成规则

- 默认让 H3 提示词描述一个完整连续 MG 动画；真正的生成由所选入口的执行适配层负责。
- 默认不生成静态分镜图，不拆多段，不做多段合成。
- 如果口播过长，先建议用户缩短或确认是否拆成多条 MG 口播动画；不要擅自拆多段。
- 默认不添加普通底部字幕；画面文字只作为关键词、短句、步骤标签、数据标签、UI 标签、产品发布片标题或品牌短语。
- 无口播输入时，若用户已明确交付目标且可用合理默认值完成，直接写提示词；只有口播或画面文字的缺失会改变交付目标时才提问。
- H3 提示词必须强调：整体效果像一支完整产品 MG 动画或高端产品界面演示短片，而不是几张静态图轮播。

## 禁止事项

- 创作方案、真实素材或授权缺失时不生成最终 MG 动画。package CLI 还须核对当前精确文件 hash 的明确批准或适用持续授权。
- 不要把需要用户作出的真实边界决定藏在默认值里；已有有效确认或当前指令已明确的创作选择直接复用，不重复提问。
- 不要沿用旧流程中的“静态分镜图确认 → 多段 MG 动画片段 → 合成”链路。
- 不要把整段口播做成底部字幕。
- 不要让画面只展示产品图轮播或 PPT 式硬切。
- 有产品图时不要忽略产品图保真；无产品图时不要虚构真实品牌、真实 Logo、真实系统界面或真实包装文字。
- 不要把虚构概念产品误写成真实品牌产品。
- 不要把 H3 提示词写成泛泛的“高级 MG 动画”，必须包含生成规格、产品设定、整体风格、核心结构、秒数分镜、文字显示、Voiceover、转场和音频提示。
- 不要加入歌词、嘈杂人声或盖过口播的音乐。
- 不要让 Skill 直接操作 ComfyUI、数据库或视频提供方；这些属于 LFO runtime 的职责。
