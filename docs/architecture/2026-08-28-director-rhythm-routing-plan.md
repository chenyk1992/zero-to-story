# 导演节奏、镜头关系与生成模式优化实施计划

## 1. 目标与范围

本方案面向所有 `zero-to-story` 项目，集中解决三个已经在《一蓑烟雨》中复现的问题：

1. 分镜写清了动作，却没有稳定写清摄影机位置、人物朝向、视线和运动轴线。
2. 2×3 六格板被直接翻译成 5–6 次切镜，导致 10–15 秒 Clip 节奏平均、紧张不紧张、舒缓不舒缓。
3. 生成策略习惯性选择 R2V，没有让 T2V、I2V、FL2V 和 R2V 在各自擅长的场景中工作；切换模式时又可能丢失人物、环境和风格连续性。

本轮不重写 LFO 架构，不引入规则引擎，不让 Runtime 理解故事板语义。改动集中在创作 Skill、故事板模板、H3 提示词交接、创作侧 QC，以及极少量适配器溯源字段。

## 2. 核心设计

### 2.1 拆开 Beat、Camera Setup 与 Panel

- `Beat`：故事或表演发生的可见变化。
- `Camera Setup`：实际摄影机机位；只有 Setup 改变才代表切镜。
- `Panel`：一次 4–15 秒生成任务，继续对应一个 Clip 和一张 2×3 六格板。

六格板继续保留，但六格改为六个有序的“可见时刻”，不再等于六个剪辑镜头。相邻格可以属于同一个 Setup，表示同一长镜头中的动作发展。P002 起左上格仍是零时长边界锚点。

H3 提示词中的 `[Shot N]` 只来源于 Camera Setup；不能因为分镜板换了一格就自动增加一次 cut。

### 2.2 AI 是导演，规则只做技术兜底

导演 AI 在看完整故事后先决定：

- 情绪压力如何上升、保持、释放或停顿。
- 每场戏采用长镜头、少量切镜还是快速蒙太奇。
- 每个 Setup 的机位、轴线、人物朝向、视线目标和运动方向。
- 哪些身份、场景或首尾状态必须被视觉锚定。
- 推荐的 H3 模式及其创作理由。

确定性校验只阻止能力不兼容的组合，例如 R2V 冒充精确首帧锁、I2V 缺少首帧、T2V 承担主要角色正脸强一致性。它不替 AI 设计节奏，也不按题材机械分镜。

### 2.3 模式选择发生在故事板阶段

`zero-to-story` 为每个 Panel 形成生成控制意图和推荐模式；`h3-prompt-writing` 检查兼容性并按该模式编译正式提示词。若素材与模式冲突，返回故事板阶段修正，不允许提示词 Skill 静默换模式或重新导演。

LFO 仍只接收最终 operation、素材绑定和提示词，并执行现有 operation/reference 校验。

## 3. 故事板最小结构调整

### 3.1 项目视觉圣经

在现有角色表和场景表中各增加一个简短、可复用的文本锚点，不新建独立数据库：

- `人物文本锚点`：只写跨镜稳定的年龄段、脸型、发型、体型、服装主色和标志性道具。
- `场景文本锚点`：只写跨镜稳定的空间结构、材质、主色、光源、时间天气和辨识物。
- `可变状态`：雨湿、尘土、伤势、手持道具等随剧情变化的信息继续放连续性账本，不混入永久锚点。

T2V 必须使用当前镜头所需的文本锚点；I2V 以首帧为主，只补充首帧无法表达的稳定约束；R2V 以实际参考素材为主，不重复堆砌整份角色卡文字。

对于反复出现且空间布局重要的场景，只在确有需要时生成一张彩色场景关键帧。一次性空镜不要求创建场景卡。

### 3.2 全章节奏图

在拆 Panel 前增加一张短表：

| 段落 | 戏剧目标 | 压力曲线 | 建议时长 | 主导拍法 | 预计切镜范围 | 声音策略 |
|---|---|---|---:|---|---:|---|
| [段落] | [观众此处应获得什么] | 上升/保持/释放/停顿 | [秒] | 长镜头/少切/快速切换 | [范围] | [环境声/对白/静默/声桥] |

这张表由导演 AI 根据完整故事生成。Panel 数和时长服从节奏图，同时保持单段 4–15 秒；不再先按默认 10 秒均分故事。

### 3.3 Camera Setup 表

用一张表代替把所有信息塞入“画面描述”长句：

| Setup | Panel | 时间范围 | 覆盖分镜格 | 与前 Setup | 机位/景别 | 轴线侧 | 人物朝向 | 目标/视线 | 屏幕运动 | 运镜 | 锁定末态 |
|---|---|---|---|---|---|---|---|---|---|---|---|

规则：

- 相邻分镜格使用同一 Setup ID，表示同镜继续，不切镜。
- 只有 `与前 Setup=cut` 才生成新的 H3 `[Shot N]` 和时间戳。
- 涉及追逐、对话、交接和主观视角时，机位、轴线侧、人物朝向、目标/视线、屏幕运动不得省略。
- 空镜、纯物件特写等不适用字段可明确写 `N/A`，不为了填表虚构关系。
- 每次 cut 必须带来新的信息、视点、空间、时间或反应；否则合并为同一 Setup。

### 3.4 Panel 生成策略表

每个 Panel 只记录以下事实和一句理由：

| Panel | 推荐模式 | 精确首帧 | 精确尾帧 | 必需视觉参考 | 连续/硬切 | 选择理由 |
|---|---|---|---|---|---|---|

不引入分数模型。模式兼容规则保持简单：

- T2V：无精确帧、无不可替代的视觉参考；适合空镜、氛围、一次性环境、弱身份远景和插入镜头。
- I2V：需要从上一真实尾帧或批准彩色关键帧准确起步；关键人物和关键环境应已在首帧中。
- FL2V：需要准确首尾状态，且主要是一条连续运动路径。
- R2V：需要多份关键身份/场景参考，或明确进入新机位的硬切；不能声称精确首帧锁。

以下情况在创作交接前必须退回：

- T2V 承担反复出现的主要角色中近景正脸，却没有可接受的身份漂移理由。
- I2V 在首帧外新增必须严格一致的重要人物或场景主体。
- FL2V 同时承载多次切镜、复杂多人表演和大量普通参考。
- R2V 把上一尾帧描述成精确 first-frame lock。

## 4. 黑白分镜板调整

继续一次生成 2×3 六格板，不拆成六张图，也不增加新的板型。

分镜 Prompt 增加：

- 每格标注其所属 Setup 的创作输入，但画面中仍禁止出现文字或编号。
- 同一 Setup 的连续格保持相同机位和轴线，只改变人物动作、距离或构图进程。
- 新 Setup 才允许改变机位；改变时必须服从 Camera Setup 表中的轴线和视线关系。
- 六格允许表现同一个长镜头的多个关键时刻，不要求每格产生新剧情信息。
- P002 起左上格继续作为零时长边界锚点，不参与 Setup 时长和 H3 切镜计数。

## 5. H3 提示词交接调整

`zero-to-story` 向 `h3-prompt-writing` 交付：

- 当前 Panel 的 Camera Setup 表和精确时间范围。
- 每个 Setup 覆盖哪些分镜格；哪些是同镜继续、哪些是真正 cut。
- 机位、轴线、人物朝向、目标/视线、屏幕运动和锁定末态。
- 当前模式、选择理由、实际可用素材及其用途。
- 当前镜头需要的人物文本锚点、场景文本锚点和可变状态。

`h3-prompt-writing` 增加以下规则：

- 不把六格自动展开成六个 `[Shot N]`；按 Setup 数量生成镜头。
- 每个空间相关镜头必须在自然语言中明确摄影机观察方向、人物相互朝向、视线目标和运动方向。
- T2V 使用 canonical 文本锚点建立人物/环境；不临时改写出另一套外貌和场景。
- I2V 从 Picture 1 已完成状态立即向前发展，只补充稳定约束，不能回卷边界动作。
- R2V 只引用真正必要的素材，并写清每份素材负责身份、环境、构图还是运动。
- 如果所选模式无法消费必需素材，停止并返回冲突，不静默删除素材或改模式。

## 6. 生成前与生成后检查

### 6.1 生成前导演检查

每个 Panel 在调用 H3 前检查：

- 六格已映射到一个或多个 Camera Setup。
- H3 镜头数等于 Setup 数，而不是分镜格数。
- 每次 cut 都有明确的新信息理由。
- 镜头时长由表演和信息量决定，没有默认平均分配。
- 空间相关 Setup 的机位、轴线、朝向、视线和运动方向完整。
- 模式与首尾帧、人物身份和参考素材兼容。
- T2V/I2V 已获得所需文本锚点；需要强身份但首帧无法提供时已改用关键帧或 R2V。

检查由导演 AI执行，以具体事实和一行结论记录，不实现复杂评分器。

### 6.2 生成后问题分类与返修路由

视频理解只使用有限类别，避免无限扩张：

| 问题 | 首选返修位置 |
|---|---|
| 人物朝向、视线或越轴错误 | Camera Setup 表与分镜板 |
| 镜头节奏平均、该停未停或该快未快 | 全章节奏图与 Setup 时间范围 |
| 动作/场景重复或边界回卷 | transition ownership 与下一 Panel 首动作 |
| 人物身份漂移 | 文本锚点、关键首帧或升级为 R2V |
| 环境布局/光色漂移 | 场景锚点、场景关键帧或后期色彩匹配 |
| 模式无法完成动作或控制过重 | 调整 T2V/I2V/FL2V/R2V，不继续堆提示词 |
| 随机畸形或偶发物理错误 | 保持创作方案，只重试当前 Clip |

同一根因连续两次失败后必须改变分镜、模式或素材策略；不能只换 seed。

### WP3：模式选择与提示词编译

修改：

### WP4：最小执行边界调整

原则上不修改 LFO Runtime 的故事语义。复用当前 operation/reference 校验。

仅在确有审计价值时修改：

- `src/lfo/skill_adapter/zero_to_story.py`
- `tests/skill_adapter/test_zero_to_story.py`

最多把 `setup_ids`、`storyboard_revision` 等不透明溯源信息透传到 `source_context`；不在适配器中实现节奏评分、导演决策或自动模式选择。

### WP5：QC 返修闭环

修改：

- `.agents/skills/zero-to-story/references/video-qc.md`
- `.agents/skills/zero-to-story/assets/storyboard_brief.template.md`

内容：加入有限的问题类别、根因与返修位置；保留现有单片 QC、尾 2 秒 + 头 3 秒边界 QC 和重试止损。

### WP6：行为验证与实际生成

先做三个代表性样例，不立刻重跑整部《一蓑烟雨》：

1. 追逐样例：验证轴线、人物朝向、同镜推进和 I2V 尾帧接力。
2. 安静表演样例：验证 10–15 秒内 2–3 个 Setup、长停留和非平均切点。
3. 无主要人物空镜：验证 T2V 使用场景文本锚点后仍保持画质与风格。

样例通过后，再用《一蓑烟雨》的追车段、授字段和一个空镜做 9:16、0.4MP、10–15 秒 A/B 生成，由视频理解检查节奏、朝向、身份、环境和边界。只有三类样例都通过，才考虑重排或重生成整章。

## 8. 测试与验收

### 静态与单元测试

- 运行两个 Skill 的 `quick_validate.py`。
- 更新适配器时运行 `tests/skill_adapter/test_zero_to_story.py`。
- 若 operation 契约未改，不扩大到全量 LFO 测试；若改动公共契约，再运行全部 `tests/contracts/` 和全量测试。
- 使用 `git diff --check` 检查文档与模板。

### 行为验收

- 一个 Panel 的 H3 Shot 数由 Camera Setup 数决定，不再固定为五或六。
- 同 Setup 的连续分镜格不会生成额外 cut。
- 空间相关镜头全部能回答“摄影机在哪里、朝哪里看、人物面对谁、看谁、向哪运动”。
- 节奏图先于 Panel 切分，Panel 时长和切点不再机械均分。
- 每个 Panel 有明确模式和理由，且 operation/reference 组合通过现有校验。
- T2V 不承担无锚点的主要角色强一致性；I2V 不凭空引入首帧外的重要身份；R2V 不冒充精确首帧。
- 生成后问题能稳定路由到分镜、节奏、模式、素材、边界或随机重试中的一个位置。
- 三个代表样例及《一蓑烟雨》三段 A/B 均通过视频理解和人工观感复核。

## 9. 推荐实施顺序

```text
WP1 导演创作契约
  → WP2 黑白板与视觉锚点
  → WP3 模式选择与 H3 编译
  → WP5 QC 返修闭环
  → WP4 必要的最小适配器调整
  → WP6 三类样例和《一蓑烟雨》A/B 验证
```

先让创作输入和提示词交接成立，再决定是否需要改代码。除非行为验证证明现有执行边界不够，否则不扩展 LFO Runtime。
