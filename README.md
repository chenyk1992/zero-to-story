# zero-to-story

项目自有代码采用 [MIT](LICENSE)，第三方内容见[许可说明](THIRD_PARTY_NOTICES.md)。开发检查见[贡献指南](CONTRIBUTING.md)，公开源码准备见[发布检查](guides/open-source-release.md)。无本机素材依赖的画布示例见 [minimal-canvas.json](examples/minimal-canvas.json)。

本 README 是新手入口。长期生产规范与操作参考位于 `guides/`，随代码分发；本地迭代计划、维护记录和复盘放在 `docs/`，不提交到 Git。

这是一个以节点画布为唯一生产入口的故事创作工作空间。可以按故事或章节组织角色参考、故事板、电影画面分镜板、提示词、图片与视频；支持分类搜索、分区、组件编辑与连线，SQLite 自动保存。点击成品可以预览实际媒体、查看本次冻结参数并跳转关联资料。

所有生产任务先遵守[项目共享生产规则](guides/ai-system-prompt.md)；[Skill 路由](guides/ai-skill-routing.md)只说明职责边界。

从项目根启动：

```powershell
./scripts/start_canvas.ps1
```

首次使用先安装项目依赖并构建页面，步骤、对话操作和已知接入边界见[画布使用指南](guides/canvas-guide.md)。新增 Skill、能力描述和 MCP 配置都限定在当前项目。

本地 Comfy 视频走一条固定链路：页面确认后，画布服务冻结输入并创建 `queued` 运行；服务内部脚本 worker 启动 `comfy-video-executor` Python adapter；adapter 通过本地 ComfyUI HTTP 接口上传素材和读取 `/object_info`，再同步调用一次官方 `comfy run --wait --json`；实际视频经过媒体校验后回填画布。Comfy 不是 `pending_agent` 任务，页面确认也不会要求对话 Agent 再 claim 或再次提交。

画布使用 `VideoSubmissionGuard` 保证本机视频串行；机器级互斥覆盖一次提交和整个等待周期。若执行进程丢失，持久回执会继续阻塞未知任务，直到依据原任务证据核实结束。技术提交成功不等于内容接受；故事生产或明确要求内容验收的媒体任务，必须依据实际视频的实际末态和实际音频证据判断。

## 快速开始

Windows 新电脑先运行只读环境预检，按提示自行准备，或明确授权 Agent 分析并安装缺少的依赖。项目不会在预检或启动时自动下载安装。完整功能准备与干净仓库边界见 [Windows 使用指南](guides/windows-setup.md)。不迁移旧电脑的画布、小说、媒体或其他私有数据。

```powershell
./scripts/check_environment.ps1
```

以下安装步骤仅在用户主动选择安装后执行：

```powershell
./scripts/bootstrap_dev.ps1
cd web/canvas
npm ci
npm run build
cd ../..
./scripts/start_canvas.ps1
```

本地 ComfyUI 设置和检查见[本机环境](guides/local-windows.md)，当前 H3 模板与绑定规则见[工作流约定](guides/workflow-conventions.md)。

源码位于 `src/lfo/`，页面位于 `web/canvas/`，测试位于 `tests/`，用户视频与素材位于 `workspace/`。旧生产入口已经退役，但已有旧包、旧运行目录、最终产物和 `workspace/assets/sha256/` CAS 数据都是用户历史资产，不会因代码清理而删除、改名或搬迁。

## 新手第一步：在 Codex 中打开项目

从 Git 下载或克隆完整仓库，在 Codex 中将仓库根目录添加为本地项目，并在该项目下开始任务。首次制作建议直接使用这个本地项目目录，让画布、素材和当前任务使用同一工作区。

基本准备包括 Python 3.12、Node.js LTS（满足 20.19+ 或 22.12+）及 npm。视频与后期还需要 FFmpeg、FFprobe、官方 comfy-cli、运行中的 ComfyUI、对应自定义节点和 H3 模型。图片生成需要宿主实际可用的图片工具。可以先让 Agent 检查：

```text
请检查当前项目在这台 Windows 电脑上的运行条件。
只做只读预检，列出缺少的依赖、影响的功能和建议准备步骤，先不要下载安装。
```

按前面的快速开始步骤准备依赖并打开画布，默认地址为 `http://127.0.0.1:8765`。端口冲突时用 `./scripts/start_canvas.ps1 -Port 8766`。修改页面后重新构建，修改服务代码后重启服务。

让 Agent 核实项目 Skills 已被发现、`story_canvas` MCP 已连接。连接示例在 [.codex/config.toml](.codex/config.toml)，应从项目根使用项目解释器；没有 MCP 时仍可通过项目 Python CLI 操作同一个画布。宿主要求信任项目配置或 hooks 时，由用户在宿主界面审阅，配置文件存在不代表已加载。

普通浏览器中的画布用于编辑、确认和查看结果，不会自行承担编剧或导演工作。完成创作到成片需要保持具有相应工具的 Agent 会话可用。

## Skill 是什么，怎么用

Skill 是 Agent 按需读取的专业工作说明，可以包含模板、参考资料和脚本。项目 Skills 位于 [.agents/skills](.agents/skills)，随仓库提供，无需复制到全局目录。它们不会因为出现在目录里就自动执行，也不会凭空提供图片工具或模型账户。

你可以直接用自然语言描述任务，让 Agent 选择匹配的 Skill；也可以明确写出 Skill 名称。支持的 Codex 界面允许用 `$skill-name` 显式引用，选择器入口以当前界面为准。如果列表中没有项目 Skill，让 Agent 检查工作目录和文件是否存在，必要时重新加载项目。官方说明见 [Build skills](https://learn.chatgpt.com/docs/build-skills)。

| 你想做什么 | 项目 Skill | 示例 |
|---|---|---|
| 写短剧、人物和分集 | `short-drama-screenwriter` | “写一集悬疑短剧，先交剧本。” |
| 把小说或剧本变成镜头和视觉资产 | `zero-to-story` | “把这段故事拆成约 30 秒的竖屏分镜。” |
| 写单段 H3 提示词 | `h3-prompt-writing` | “为已确定的第 1 段分镜写提示词，先不生成。” |
| 整理画布、导入素材和查看运行 | `canvas-workspace` | “把已定稿分镜保存为视频节点，先不确认运行。” |
| 制作数字人口播 | `virtual-presenter` | “按这段文案设计连续数字人口播。” |
| 制作 MG 产品讲解动画 | `mg-voiceover-animation-generator` | “把这个功能做成 30 秒 MG 口播动画方案。” |
| 为讲稿安排 B-roll 副镜头 | `transcript-broll-planner` | “为这份逐字稿规划 B-roll，保留原有事实。” |
| 拆解参考视频 | `video-deconstruct-analyzer` | “分析这个视频的镜头、节奏和声音。” |
| 用 MiMo 理解视频 | `mimo-video-understanding` | “用 MiMo 分析视频中人物动作的时间顺序。” |
| 克隆已获授权的声音 | `voice-clone` | “我有权使用这段参考音频，请检查音色克隆条件。” |
| 改善文本表达 | `shuorenhua` | “清理这段口播稿的模板腔，保留事实。” |

例如可以发送 `$zero-to-story 请把下面这段小说做成分镜方案，先不生成媒体`，也可以写“请使用 zero-to-story Skill”。只要剧本就只交剧本，只要提示词就只写提示词。**保存画布草稿不等于生成媒体**；真正生产需要页面确认或对话中的明确授权。

`comfy-video-executor` 是服务内部执行 Skill：确认视频请求后，worker 自动调用它。用户不用手动运行，Agent 也不能另起一份脚本重复提交。MiMo、音色克隆等 API 需要对应密钥和账户；可选 mmx 需要另行接入 CLI、认证及外部 Skill。Seedance 当前尚未接入。

## 先完成一个短片

建议先做约 20–30 秒、人物少、场景简单的短片，验证从创作到成片的路径。素材可放在 `workspace/projects/my-first-film/` 或通过画布导入，也可直接在对话中提供故事。不要把私人小说和参考素材提交到 Git。

先发送规划请求：

```text
请用 zero-to-story，把下面的故事规划成约 24 秒的 9:16 短片：
雨夜，一位老人发现门口有一只淋湿的小猫，犹豫片刻后把它抱进屋里。
风格温暖、写实，不需要对白。先完成故事板、角色设定和画布草稿，不生成媒体。
列出建议的片段划分、必要参考图，以及正式生产前还缺少的参数。
```

一个 Panel 对应一次视频生成，不等于整部成片。查看方案并补齐画幅、时长、声音、像素预算 `megapixels`、采样模式 `sampler_profile` 和步数 `steps`。不熟悉参数时，让 Agent 依据当前能力目录解释有效选项并建议，不照搬别人的机器参数。

确认方案后，可以授权：

```text
按刚才确认的故事板和制作参数执行本次短片。
授权生成本片必要的参考图，并通过画布逐 Panel 使用本地 Comfy H3 生成视频。
在本片创作方案和已确定参数范围内，由你完成具体提示词与素材绑定，
在已有授权内确认当前精确输入，不必每段重复询问。
失败、状态未知或需要额外生成修复时先说明，不自动重提。
完成实际片段验收后，按故事顺序剪辑、处理声音并合并成 MP4，做一次最终视听检查。
不要下载安装依赖，不调用我未选择的付费后端。
```

若希望先审每段提示词，把授权改成“每段正式生成前等我确认”。Agent 应沿用已有明确授权，不能把没有回复当作同意。

## 在 Codex 中用目标模式持续做到成片

在支持的 Codex 桌面端、CLI 或 IDE 中输入 `/goal`，然后填写目标；桌面端也可使用当前界面显示的 Goal 入口。目标写清**交付物、约束和完成标准**。如果还没决定做什么，先在普通对话中完成规划，再设生产目标。官方操作见 [Long-running work](https://learn.chatgpt.com/docs/long-running-work)。

先确认上一步的制作参数，再将下面的目标交给 Codex。替换故事和规格即可；需要限制费用或生成次数时，一并写出明确上限：

```text
目标：按本任务已经确认的故事板和制作参数，完成约 24 秒、9:16、
温暖写实风格、无对白的“雨夜收留小猫”短片，交付可播放的最终 MP4。

按 AGENTS.md 和项目共享生产规则工作，按需使用项目 Skills。
由你承担导演、提示词、素材准备、画布操作、视频生产、验收和后期交付。
允许将明确的独立创作或检查工作交给子代理，主会话负责衔接并处理实际结果。

授权范围：本片必要参考图使用当前已核实可用的宿主图片工具；
视频只用画布内本地 Comfy H3。沿用已确认的画幅、像素预算、采样模式和步数，
由你在方案范围内完成各 Panel 的精确提示词和素材绑定，并确认一次运行。
不安装依赖，不增加未选择的付费服务，不自动重试失败或未知请求。
遇到缺失参数、工具、额度或超出授权的修改，说明具体缺口。

不要停在方案、画布草稿或单个片段完成。
实际结果返回后处理验收，并继续下一项已授权且输入齐全的工作。
后段需要真实尾帧时，先接受前段实际视频，再提取并绑定尾帧。
等待时遵守项目接续规则；无法维持接续时留下明确的待接手状态。

将已接受片段按故事顺序剪辑，统一尺寸、帧率和音频规格，
保护有效声音，处理必要接缝，输出到当前项目的 final 目录。
检查最终文件的画面、声音和接缝；工具无法验证某项时，保留未核实项。

完成标准：最终 MP4 实际存在且可播放，内容符合已确认方案，
完成必要后期和一次完整视听检查，并给出可点击的成片路径。
不能以提示词、生成成功状态或片段列表替代最终成片。
```

目标模式不会增加工具权限、代替生产授权或保证依赖永远在线。保持电脑、Codex 和 ComfyUI 可用；关闭应用或断网前先暂停。当前版本没有 `/goal` 时，可在普通任务中提交相同目标并继续同一会话，但不要把它描述成已启用原生目标模式。

工作中可在同一任务补充要求或问进度。暂停时明确发送“暂停本片后续生产并记录暂停状态”，同时暂停 Goal；恢复时要求核对原运行和授权后继续。暂停主会话不等于取消已经提交到 ComfyUI 的任务，不能为“恢复”重复提交。项目 hooks 与后台接续须按[接续指南](guides/canvas-continuation.md)核实加载，不能仅因开启 Goal 就宣称可以关机后或无限期无人值守执行。

## 从片段到最终成片

正常路径是：**故事／文案 → 故事板和参考资产 → 单 Panel 提示词 → 画布确认 → 实际视频 → 片段验收 → 剪辑与声音处理 → 合并成片 → 最终视听检查**。

生成成功只表示技术上拿到了文件，Agent 仍应检查画面、声音和剧情要求。后期以实际采用片段为源，必要时使用 FFmpeg 统一规格、剪辑和合并。字幕、配音、音乐或片头片尾只有纳入本次要求且素材与授权可用时才添加。

已经有片段时，可以直接发送：

```text
请读取当前画布中本片已接受的视频，按已确认的故事顺序完成后期并合并成片。
不重新生成视频。检查尺寸、帧率、音轨和片段接缝，保留有效声音。
输出最终 MP4；顺序或采用版本不明确时，先指出缺口。
```

原始媒体和 Run 产物位于 `workspace/projects/<project_id>/outputs/<run_id>/`，最终交付放在 `workspace/projects/<project_id>/final/`。后期创建新版本，不覆盖源文件。只有最终文件完成所需检查，才把整片目标标为完成。

## 常见问题与仓库边界

| 情况 | 下一步 |
|---|---|
| 页面提示需要构建 | 经用户选择安装依赖后，在 `web/canvas` 运行 `npm ci` 和 `npm run build` |
| 图片任务显示“需 Agent 接手” | 在具有真实图片工具的会话中接手，画布本身不附带图片模型 |
| 视频失败或状态未知 | 核查原运行和 Comfy 历史，不换编号重提或删除占用回执 |
| Agent 只交方案或片段 | 检查生产授权、缺失依赖，以及目标是否明确包含最终 MP4 和最终验收 |
| 换电脑后画布为空 | 干净部署从空画布开始，旧电脑私有数据不会随 Git 搬迁 |

代码、项目 Skills、宿主配置、`guides/`、测试和公开示例随 Git 分发。`docs/` 只存本地迭代记录，不作为运行依赖；`workspace/`、`.short-drama/`、应用数据、凭据和本机依赖环境不迁移、不提交。

README 帮助用户上手；`guides/` 中的共享规则和详细契约供 Agent 按需读取。不要把这些必需规则与迭代记录一起排除，否则新克隆的仓库无法按约定执行。
